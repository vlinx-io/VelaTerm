## v0.1.101 — 2026-08-15

### 遠端存取

- **可以選擇分享連結使用的位址——Tailscale 位址現已顯示。** 位址清單過去只接受傳統的私有 IPv4 網段,因此像 Tailscale 這樣從電信級 NAT 網段(100.64.0.0/10)配發位址的 VPN 網格,會被靜默排除在遠端存取面板和配對連結之外——儘管伺服器早已可經由這些位址連線。這些位址現在會列出;VPN 通道排在最後,永遠不會成為預設值。面板中新增的 IP 選擇器(啟動前與執行中皆可見)會列出每個候選位址及其網路介面名稱,並標記 VPN 通道;選擇某個位址後,其 URL 會移到最前,配對連結也會以該主機重新產生,因此複製的連結在只能透過 VPN 連上本機的裝置上也能直接使用,無需手動修改 URL。配對連結下方的 QR code 可直接用手機掃描。選擇會被記住;若所選介面消失,面板會回退為「自動」,但不會忘記你的選擇。伺服器本身維持不變,仍在所有介面上監聽。選擇一個在伺服器啟動後才出現的位址(例如稍後才連線的 VPN),現在複製的 URL 和 QR code 也會立即更新,而不再是只有配對連結跟隨、其餘要等到下次重新啟動;VPN 通道在所有平台上都排在 LAN 位址之後,伺服器停止時所做的選擇會決定啟動後的第一個配對連結,重疊的連結重新產生也不會再用舊連結覆蓋新連結。

- **分享現在可以在重新啟動後繼續使用。** 過去配對權杖在伺服器每次啟動時都會重新產生：只要結束並重新開啟 VelaTerm，所有已分享的連結就會悄悄失效，每支手機都得重新配對。現在，權杖、已配對裝置和裝置封鎖清單都儲存在資料目錄下一個僅擁有者可讀的檔案裡：已配對的裝置在重新啟動後仍可透過儲存的 URL 直接重新連線（存取密碼仍是必要的第二重驗證），被撤銷的裝置也依然保持撤銷狀態。VelaTerm 還會記住分享處於開啟狀態：在伺服器執行時結束應用程式，下次啟動會自動在同一連接埠恢復服務——桌面應用程式和透過 `--serve` 執行的無介面伺服器都是如此；如果是您自己停止的伺服器，下次啟動則不會自動開啟任何東西。即使自動啟動失敗（例如連接埠被占用），應用程式也會正常啟動，遠端存取面板會顯示失敗原因。連接埠欄位現在會記住實際使用過的連接埠，而不再重設為預設值；「重新產生連結」仍是明確的作廢開關：它會立即簽發新權杖、讓所有舊連結失效並覆寫儲存的狀態。存取密碼本身永遠不會寫入磁碟——只儲存一個記憶體困難型雜湊（Argon2id）。

### 安全性

- **已配對裝置無法再管理共用本身。** 先前,任何已配對的瀏覽器都能呼叫與桌面應用程式相同的管理命令——建立新的配對連結(這同時會清空裝置封鎖清單)、列出並撤銷其他裝置、停止或重新設定伺服器——而設定存放區會把完整的設定表交給每個用戶端,其中包括存取密碼的記憶體困難雜湊,以及下次啟動要讀取的自動啟動設定。管理命令現在僅限桌面應用程式與 Electron 外殼使用;設定 API 會在已配對裝置的每次讀取中過濾遠端存取相關鍵與 Gitea 權杖,並拒絕對它們的寫入。已配對裝置保留配對的本來用途——終端機工作階段與完整的 shell 存取——但再也無法讀取密碼驗證值、邀請或驅逐其他裝置,或竄改下次啟動使用的連接埠。讀取、寫入或刪除已儲存機密的命令——Gitea 權杖與已記住的主機密碼——現在對已配對裝置同樣會被拒絕;接收路徑的命令——讀取、預覽、寫入、建立、重新命名和刪除,以及顯示檔案的 git 差異或選擇複製儲存庫的目標資料夾——會先解析符號連結，再拒絕位於 VelaTerm 自身資料目錄內的路徑(配對狀態與金鑰就存放在那裡),其他所有路徑照常可用,因此遠端檔案瀏覽與編輯不受影響。一項測試會列舉每個接收路徑的遠端命令,新命令無法悄悄繞過這項檢查。當這些保護拒絕某個請求時,瀏覽器現在會顯示經過翻譯的訊息,而不是原始的英文錯誤。

- **撤銷裝置或重新產生連結,在雙執行個體配置下也不會再遺失。** 在開啟自動啟動的無介面 `--serve` 伺服器上,兩個伺服器執行個體各自持有已儲存配對狀態的副本並整體回寫:透過其中一個完成的撤銷或新配對連結,可能被另一個悄悄還原。同一處理程序內的所有執行個體現在依資料目錄共用單一配對狀態:撤銷與輪替立即在所有位置生效,檔案只由一處寫入,並且在真正的重新啟動之間仍是權威資料來源。

- **反覆失敗的登入會被限速。** 存取密碼的驗證使用 Argon2id,代價刻意高昂——而任何連得到連接埠的人都可以嘗試。同一位址失敗五次後,後續嘗試會在任何雜湊計算開始之前被拒絕一分鐘;雜湊計算本身現在也在伺服器事件迴圈之外執行,並對並行驗證數量設有硬性上限:大量錯誤密碼既不能再用記憶體困難雜湊拖垮伺服器,也不能拖慢已連線裝置的回應。此限速器僅存在於記憶體中,隨伺服器重新啟動而重置;真正的屏障仍是配對權杖與密碼。該限制現在由使用同一資料目錄的所有伺服器實例共享——`--serve` 雙實例設定不再使嘗試次數加倍;並且在密碼驗證開始前就會保留一次嘗試,使來自同一位址的並行請求無法鑽過限制。被限流的瀏覽器現在會在登入畫面看到專屬的限流訊息,而不是被告知密碼錯誤;限流也不再像密碼錯誤那樣被記住:等待結束後,下一次嘗試無需重新整理頁面即可再次通過。中途放棄的嘗試——密碼還在驗證時分頁就被關閉——現在會立即釋放其保留的名額,而不是在這一分鐘剩下的時間裡繼續計入該位址;登入成功也只釋放自己的保留,而不再清空該位址的全部紀錄:在共享網路位址背後,某人正確登入不再重設攻擊者的嘗試額度,已記錄的失敗只隨其所在的一分鐘過期。

- **磁碟上與記錄中的機密獲得更謹慎的處理。** 保存配對狀態的檔案與端對端加密金鑰現在從建立那一刻起就僅擁有者可讀,而不是先寫入再收緊權限;存有密碼雜湊的工作階段資料庫同樣僅限擁有者存取。無介面 `--serve` 不再把配對連結中長期有效的機密列印到記錄:當輸出不是終端機時,連結會被隱藏,只顯示一則提示;`--print-pairing` 可明確恢復原行為。裝置註冊表上限為 32 筆,名稱長度受限,已配對用戶端無法讓儲存檔案無限膨脹;儲存撤銷或新連結失敗時,錯誤現在會回傳給呼叫方,而不是只留在記錄裡。自動啟動不再取代已手動啟動的伺服器,過期的自動啟動錯誤在您自行停止伺服器後即會消失。

### 修正

- **現在也可以在 Electron 外殼中管理配對。** 產生配對連結、列出已配對裝置和撤銷裝置先前只以桌面（Tauri）命令的形式存在；Electron 外殼和瀏覽器用戶端使用的 WebSocket 分派器會回應 "Unknown command"，導致遠端存取面板在那裡無法使用。現在這三個命令在兩條傳輸通道上都經過同一套核心函式，兩者不會再產生落差；回歸測試涵蓋了新的分派路徑，包括對一個執行中的本機伺服器實際產生配對連結。

- **內建瀏覽器啟動更快。** 現在，每個瀏覽器分頁都提供一鍵開啟 ChatGPT、Claude、Gemini 和 Google 的捷徑。專案和群組的內容選單也可以直接在工作階段樹的相應位置建立固定瀏覽器頁面。

### 圖片和文件

- **在 macOS 上可靠地貼上圖片路徑。** 當 WebKit 沒有將複製的圖片公開為檔案時，VelaTerm 現在會從系統剪貼簿讀取圖片，並仍將其作為檔案路徑上傳，而不會無聲地退回代理程式原生的圖片預留位置。遠端視窗會一律顯示圖片貼上設定、說明為何必須使用檔案路徑模式，並停用無法使用的原生選項。
- **將圖片貼到原始碼文件。** 原始碼編輯器現在支援貼上剪貼簿圖片。已儲存的 Markdown 文件會把圖片放在文件旁的 `assets/` 目錄中，並插入可攜式 Markdown 圖片語法；未儲存的草稿則會嵌入圖片資料，避免清除暫存檔時遺失。

### 介面

- **內容選單保持可見並準確對準項目。** 在右側邊緣附近開啟的選單會被正確測量和調整位置。對樹狀節點按右鍵時，現在只會醒目提示選單目標而不改變既有選取；群組選單也包含作用於該群組的終端機。
- **更清爽的編輯效果和狀態標籤。** 原始碼文字不再為 HTML 註解等字元序列顯示箭頭狀字型連字；用量百分比會明確標示為已使用；宿主 WebView 無關的原生內容選單也不會再出現在 VelaTerm 自有選單後方。

### 修正

- **Codex 保持在一般終端機歷程中。** 由 VelaTerm 啟動的 Codex 工作階段現在使用行內終端機模式，因此按 Esc 中斷或返回時，不會再切換終端機畫面緩衝區並讓回捲檢視跳到頂端。使用者自己的 Codex 設定不會被修改。
