## v0.1.104 — 2026-08-25

### AI 智慧體

- **子任務確認卡給出的是每個智慧體自己的模型，以及它真正認得的思考強度參數。** 確認卡過去不管面對哪個智慧體，都用 `--model` 和 `--effort` 拼啟動參數，但只有 Claude、Kiro 和 Antigravity 用這個寫法——Grok 和 Zoo 叫 `--reasoning-effort`，Cline 叫 `--thinking`。於是給其餘智慧體選一次思考強度，等於往命令列裡塞了一個它從沒聽過的參數，會話直接起不來。現在每個智慧體都給出自己的參數名和取值範圍。模型控制項也跟著各家 CLI 的實際能力走：能列出目錄的（OpenCode、Grok、Crush、Antigravity、Cursor、pi、Kiro）會去問它要，給出真實清單；只有固定幾個的（Claude、Codex、Kimi Code）給出那幾個；其餘的給一個文字方塊，附上它期望的寫法範例。沒裝或者沒登入的智慧體會直接說清單取不到，而不是一直轉圈。選「Default」現在是把繼承來的設定清掉，而不是留著舊值；選思考強度也不會再順手把父會話傳下來的模型弄丟。

- **從 Kimi Code 會話衍生的子任務仍然是 Kimi Code。** 衍生時用來繼承父會話智慧體的那張表裡漏了 Kimi Code，於是它的子會話會悄悄退回預設智慧體。

### 工作區

- **分組建好之後還能改綁 worktree。** 過去 worktree 只能在建分組的時候選，選完就定死，想換只能把分組刪了重建。現在在分組上按右鍵選「Move to Worktree…」，可以新建一個 worktree、綁到已有的某一個，已經綁過的分組則是改指向。改動只落在分組本身：分組裡已有的會話保持它們建立時的目錄——正在跑的會話沒法在自己腳下換目錄——之後新建的會話才會起在這個 worktree 裡。

- **鏡像模式現在涵蓋整棵左樹。** 它此前同步的是選取項目和摺疊的面板，搜尋框、狀態與標記篩選留在本機，理由是同步過去會打斷正在查東西的人。這個理由說反了：鏡像的意思是兩個視窗持有同一份狀態，不是一邊把另一邊的按鍵重播一遍——這邊開著的篩選條件，那邊也開著。真正打斷人的，恰恰是兩邊看到的樹不一樣。現在左樹的每個投影都跟著走：分割結構、投影的名稱、搜尋詞、狀態與標記篩選，還有各自獨立的摺疊狀態。快照格式升到第 2 版，版本對不上的一方會停止鏡像，而不是套用半幀內容，所以升級期間一直開著的視窗重新整理一下即可。

### 介面

- **macOS 上關視窗問的問題和結束程式一樣了。** ⌘Q 和選單裡的結束都會走應用自己的確認，但紅色關閉按鈕是直接把視窗銷毀——而承載確認對話框的 webview 就在那個視窗裡。結果要麼根本沒有確認，要麼只剩下降級的原生對話框：沒有「儲存工作區」勾選方塊，文字也沒翻譯。現在三個平台都會先把視窗留住，等你回答。

- **「儲存工作區」預設勾選，而且改了之後記得住。** 丟掉版面配置的代價比多存一份用不上的快照大，所以這一項預設是勾起來的。它此前還會忘事：這個設定要經過 400 毫秒防抖才寫入資料庫，而結束程式會在這個時間窗內把行程殺掉，下次啟動對帳時便以舊值為準，把你的改動改了回去。現在結束前會先把這次寫入刷下去，並且最多等 600 毫秒，後端卡住也不會讓確認按鈕一直轉。（由 FarhadGSRX 貢獻。）

- **遠端連線面板裡的密碼可以看明文。** URL 密碼和 SSH 密碼各有一個眼睛按鈕，在遮罩和明文之間切換。顯示狀態只屬於這個輸入框，面板關掉就重設，不會把密碼留在畫面上。

- **左欄篩選器的角標會把所有生效的篩選條件都算進去。** 標記篩選此前只是把按鈕點亮、不作聲，於是兩個條件同時開著時角標卻顯示 1。現在狀態和標記一起計數，和下拉選單裡打勾的數量對得上；只開一個狀態篩選時仍然保留那個彩色圓點。

### 修復

- **macOS 上的自動更新恢復正常。** v0.1.103 的安裝包裡混進了 `._VelaTerm.app` 這類 AppleDouble 伴生項目，而更新器會去掉每條路徑的第一層——這類項目去掉之後就成了空路徑——於是它乾脆拒絕解壓。兩個架構都中招，所有用 macOS 的 v0.1.103 使用者都卡在了那一版。現在打包不會再寫出這些項目。

- **應用主題與系統不一致時，原生控制項跟著應用走。** 切換主題只改了應用自己的配色，沒有同步 `color-scheme`，而那個值只在啟動時按系統偏好種下一次、之後再沒變過，於是系統深色 + 應用淺色時，核取方塊、下拉選單和捲軸還是深色的。（由 FarhadGSRX 貢獻。）

- **乾淨 clone 下來能編譯了。** Rust crate 在編譯期就要嵌入 `../dist`，而 dev 命令並不產出這個目錄，於是新複製的儲存庫還沒跑起來就先編譯失敗。現在建置指令碼會在目錄缺失時把它建出來。（由 FarhadGSRX 貢獻。）

## v0.1.102 — 2026-08-23

### AI 智慧代理

- **智慧代理預設組合：多個相容的 CLI 可以並排使用。** 過去每種智慧代理都寫死了一個執行檔，於是一個分支版本、一個 nightly 建置，或是另一個說著同樣協定的 CLI，都沒有地方安放——只能去改現有類型的啟動參數，改完原來的那個就沒了。現在一個預設組合自帶執行檔、圖示和啟動參數，並出現在新增工作階段選單裡，與內建類型並排。工作階段會記下自己是由哪個預設組合建立的，因此 Fork 出來的工作階段仍然用同一個執行檔；在桌面端建立的預設組合也會出現在已配對的瀏覽器和遠端用戶端上，圖示一起帶過去——因為圖示是以資料的形式傳輸的，而不是某台機器上的一個路徑。既有工作階段完全不受影響：舊版本留下的資料庫，啟動後和以前一模一樣。

- **子任務確認卡可以挑模型和推理強度，一處回答，處處生效。** 智慧代理要求衍生子任務時，確認卡現在可以選模型，智慧代理支援的話還能選推理強度，兩者都依父工作階段自己的啟動參數預先填好，因此常見情況點一下就完事。在卡片上換成另一個智慧代理，兩項會重新推導，一個 CLI 的模型名稱不會再跑到另一個 CLI 的命令列上。這張卡會出現在每個已連線的用戶端上，在其中一個上回答，其餘的會一起消失；第一個回答還會在伺服器端認領這個任務，於是在同一秒裡用手機和桌面各確認一次，也只會建立一個 worktree 和一個子工作階段，而不是兩個。

### 工作區

- **鏡像模式：所有用戶端共用同一套版面。** 終端機資料流一直是共享的——一個 PTY，一條位元組流——但圍繞它的那套排列只存在於各個用戶端自己的瀏覽器儲存區裡，因此區域網路裡開啟的瀏覽器有自己的一套分頁和分割，在一邊重新排列，另一邊毫無反應。開啟鏡像模式後，分頁、分割、目前工作階段、側邊欄選取項和摺疊的面板都會發布給每個用戶端，並被所有用戶端跟隨。開關由主機在遠端存取面板裡控制。在任何一端重新排列，另一端都會跟著變；某個工作階段離開本視窗的版面時是被卸離，而不是被終止，因此跟隨對端永遠不會結束別人的處理程序；套用對端版面時也不會把鍵盤從正在本機打字的人手裡搶走。手機不參與——手機上是兩層導覽，是另一種形態的介面，把桌面的分割樹複製過去對誰都沒有好處。

- **右欄的 Git 分頁做成了能用的 Git 用戶端。** 它以前只會列出改動過的檔案。現在它可以暫存和取消暫存單一檔案或整組檔案、捨棄變更、寫提交（含修改上一次提交），並顯示提交歷史以及每個提交涉及的檔案和差異——分成已暫存、已修改、未追蹤和已提交幾組，可以摺疊起來。路徑統一從儲存庫根目錄處理，因此在子目錄裡開啟的工作階段，操作的就是它顯示的那些檔案；處於分離 HEAD 狀態時會如實標出，而不是顯示一個叫 HEAD 的分支。

### 介面

- **⌘Q 現在問的問題和關視窗一樣。** 應用程式選單裡的結束項目原本是系統自帶的那個，按下去直接終止處理程序：按 ⌘Q 會跳過關閉按鈕會跳的「儲存工作區」確認，同一個意圖，換個方式表達行為就不一樣。現在兩條路都走同一個確認。如果顯示確認的那個視窗在這期間重新載入或當掉了，再按一次 ⌘Q 會重新詢問，並回退到原生對話框，而不是讓應用程式關不掉。

- **快速鍵提示顯示的是真正能用的按鍵。** 各平台的預設鍵位本來就不同，而瀏覽器會把 ⌘/Ctrl 加字母的組合留給自己——⌘D 是加入書籤，⌘T 是開分頁——所以當 VelaTerm 以網址方式開啟時，macOS 上應用程式自己的 ⌘ 快速鍵根本傳不到頁面。現在一般瀏覽器分頁在所有作業系統上都改用 Ctrl+Alt 這套鍵位，桌面應用程式和遠端連線視窗仍然用 ⌘。工具提示和空分頁上的提示會顯示目前實際生效的鍵位，包括你自己改過的，而不是寫死的 ⌘ 組合；終端機攔截的也正好是應用程式已經占用的那些組合，所以幫某個操作換鍵，攔截也跟著換過去。

- **字型預設涵蓋了 Nerd Font 和中日韓字型，自己填的字型沒裝會明說。** 預設清單加入了常見的 Nerd Font 和中日韓字族；手動輸入的字型會回顯並檢查一遍：系統裡沒有這個字型，設定頁會直接說出來，而不是悄悄回退到一個和你要的完全不像的預設字型。

- **macOS 上的輸入欄位不再自動大寫或自動更正。** 系統的自動首字母大寫、自動更正和拼字檢查過去對應用程式裡的每一個輸入欄位都生效，工作階段名稱和命令欄位也不例外，於是「npm」被改成了「Npm」。現在這些在所有地方都關掉了。

### Windows

- **輸入中文、日文、韓文時，預先編輯的文字和候選字視窗又看得見了。** 這兩樣先前都是隱形的——只能盲打，按下 Enter 才看到結果。原因出在我們自己的兩條 CSS 規則上：承載預先編輯浮層的容器寬度塌成了 0，浮層的 `right` 位移在這個容器裡算下來什麼都不是。候選字視窗跟著一起消失，因為作業系統是依浮層的矩形來定位它的。現在浮層重新畫出來了，配色也用上了應用程式自己的；承載它的那個隱形輸入元素在組字結束後會釋放自己占據的區域，因此在那一塊上點擊和拖曳能落到終端機上，而不是被一個一直蓋著的空元素擋住。

- **原生標題列跟隨淺色/深色設定。** 應用程式保留了系統標題列，而 Windows 在沒被告知之前一直把它畫成淺色，於是深色介面上方頂著一條白邊。現在它會與應用程式保持一致，之後開啟的視窗——例如 SSH 和遠端連線視窗——也一樣。選擇「跟隨系統」則把控制權交回作業系統，而不是釘死一個值。

- **冷啟動時那個多餘的小方塊沒有了。** 單一執行個體外掛會建立一個隱藏的訊息視窗，卻一直沒給它自己樣式裡承諾的透明屬性，於是 Windows 偶爾會把這個零尺寸視窗撐到最小尺寸，在啟動過程中畫出一個小方塊。現在它是真的透明了；單一執行個體行為沒有變化。

### 效能

- **遠端存取首屏要載入的東西少了很多。** 靜態資源現在會按需壓縮，並帶上快取驗證標記，因此第二次造訪是重新驗證而不是重新下載；語言包和終端機的選用算繪器也改成用到時才載入，不再算進首屏的那一份。兩項加起來，首次傳輸量降到原來的五分之一左右。

### 修正

- **衍生出來的子工作階段，現在和要求它的那個工作階段以同樣的方式啟動。** 子工作階段過去既不繼承父工作階段的權限模式，也不繼承它的啟動參數，於是一個略過確認在跑的工作階段，它的子工作階段起來後反而要你確認，父工作階段上釘住的模型也丟了。現在兩者都會繼承，取不到就回退到該智慧代理類型的全域預設值——和「新增智慧代理工作階段」選單用的是同一份。

- **重新連線遠端視窗不再誤報「驗證失敗」。** 視窗重新連線時，新的 WebSocket 和它取代的那個會互相競爭；失敗一方的拆除被當成驗證失敗回報，於是橫幅指責一個完全有效的配對被拒絕了。

- **群組不能再被拖進自己的子樹裡。** 把一個群組拖到它自己的某個後代上，會讓整條分支從樹上脫落，裡面的工作階段從側邊欄消失，直到手動修復資料庫才能找回。現在這個移動會被拒絕。

- **從別的工具裡啟動 VelaTerm，智慧代理輸出的顏色不會丟。** 終端機會繼承啟動它的那個程式的環境，因此從匯出了 `NO_COLOR`、`CI` 或 `FORCE_COLOR=0` 的 IDE 或智慧代理框架裡啟動，VelaTerm 裡的智慧代理 TUI 會全部渲染成單色，儘管終端機本身聲明支援全彩。現在工作階段啟動時會丟棄這些繼承來的值；你自己在 shell 設定檔裡匯出的同名變數仍然生效，因為那份設定是在工作階段內部執行的。

## v0.1.101 — 2026-08-15

### 遠端存取

- **可以選擇分享連結使用的位址——Tailscale 位址現已顯示。** 位址清單過去只接受傳統的私有 IPv4 網段,因此像 Tailscale 這樣從電信級 NAT 網段(100.64.0.0/10)配發位址的 VPN 網格,會被靜默排除在遠端存取面板和配對連結之外——儘管伺服器早已可經由這些位址連線。這些位址現在會列出;VPN 通道排在最後,永遠不會成為預設值。面板中新增的 IP 選擇器(啟動前與執行中皆可見)會列出每個候選位址及其網路介面名稱,並標記 VPN 通道;選擇某個位址後,其 URL 會移到最前,配對連結也會以該主機重新產生,因此複製的連結在只能透過 VPN 連上本機的裝置上也能直接使用,無需手動修改 URL。配對連結下方的 QR code 可直接用手機掃描。選擇會被記住;若所選介面消失,面板會回退為「自動」,但不會忘記你的選擇。伺服器本身維持不變,仍在所有介面上監聽。選擇一個在伺服器啟動後才出現的位址(例如稍後才連線的 VPN),現在複製的 URL 和 QR code 也會立即更新,而不再是只有配對連結跟隨、其餘要等到下次重新啟動;VPN 通道在所有平台上都排在 LAN 位址之後,伺服器停止時所做的選擇會決定啟動後的第一個配對連結,重疊的連結重新產生也不會再用舊連結覆蓋新連結。

- **分享現在可以在重新啟動後繼續使用。** 過去配對權杖在伺服器每次啟動時都會重新產生：只要結束並重新開啟 VelaTerm，所有已分享的連結就會悄悄失效，每支手機都得重新配對。現在，權杖、已配對裝置和裝置封鎖清單都儲存在資料目錄下一個僅擁有者可讀的檔案裡：已配對的裝置在重新啟動後仍可透過儲存的 URL 直接重新連線（存取密碼仍是必要的第二重驗證），被撤銷的裝置也依然保持撤銷狀態。VelaTerm 還會記住分享處於開啟狀態：在伺服器執行時結束應用程式，下次啟動會自動在同一連接埠恢復服務——桌面應用程式和透過 `--serve` 執行的無介面伺服器都是如此；如果是您自己停止的伺服器，下次啟動則不會自動開啟任何東西。即使自動啟動失敗（例如連接埠被占用），應用程式也會正常啟動，遠端存取面板會顯示失敗原因。連接埠欄位現在會記住實際使用過的連接埠，而不再重設為預設值；「重新產生連結」仍是明確的作廢開關：它會立即簽發新權杖、讓所有舊連結失效並覆寫儲存的狀態。存取密碼本身永遠不會寫入磁碟——只儲存一個記憶體困難型雜湊（Argon2id）。

### 安全性

- **已配對裝置無法再管理共用本身。** 先前,任何已配對的瀏覽器都能呼叫與桌面應用程式相同的管理命令——建立新的配對連結(這同時會清空裝置封鎖清單)、列出並撤銷其他裝置、停止或重新設定伺服器——而設定存放區會把完整的設定表交給每個用戶端,其中包括存取密碼的記憶體困難雜湊,以及下次啟動要讀取的自動啟動設定。管理命令現在僅限桌面應用程式與 Electron 外殼使用;設定 API 會在已配對裝置的每次讀取中過濾遠端存取相關鍵與 Gitea 權杖,並拒絕對它們的寫入。已配對裝置保留配對的本來用途——終端機工作階段與完整的 shell 存取——但再也無法讀取密碼驗證值、邀請或驅逐其他裝置,或竄改下次啟動使用的連接埠。讀取、寫入或刪除已儲存機密的命令——Gitea 權杖與已記住的主機密碼——現在對已配對裝置同樣會被拒絕;接收路徑的命令——讀取、預覽、寫入、建立、重新命名和刪除,以及顯示檔案的 git 差異或選擇複製儲存庫的目標資料夾——會先解析符號連結，再拒絕位於 VelaTerm 自身資料目錄內的路徑(配對狀態與金鑰就存放在那裡),其他所有路徑照常可用,因此遠端檔案瀏覽與編輯不受影響。一項測試會列舉每個接收路徑的遠端命令,新命令無法悄悄繞過這項檢查。當這些保護拒絕某個請求時,瀏覽器現在會顯示經過翻譯的訊息,而不是原始的英文錯誤。

- **撤銷裝置或重新產生連結,在雙執行個體配置下也不會再遺失。** 在開啟自動啟動的無介面 `--serve` 伺服器上,兩個伺服器執行個體各自持有已儲存配對狀態的副本並整體回寫:透過其中一個完成的撤銷或新配對連結,可能被另一個悄悄還原。同一處理程序內的所有執行個體現在依資料目錄共用單一配對狀態:撤銷與輪替立即在所有位置生效,檔案只由一處寫入,並且在真正的重新啟動之間仍是權威資料來源。

- **反覆失敗的登入會被限速。** 存取密碼的驗證使用 Argon2id,代價刻意高昂——而任何連得到連接埠的人都可以嘗試。同一位址失敗五次後,後續嘗試會在任何雜湊計算開始之前被拒絕一分鐘;雜湊計算本身現在也在伺服器事件迴圈之外執行,並對並行驗證數量設有硬性上限:大量錯誤密碼既不能再用記憶體困難雜湊拖垮伺服器,也不能拖慢已連線裝置的回應。此限速器僅存在於記憶體中,隨伺服器重新啟動而重置;真正的屏障仍是配對權杖與密碼。該限制現在由使用同一資料目錄的所有伺服器實例共享——`--serve` 雙實例設定不再使嘗試次數加倍;並且在密碼驗證開始前就會保留一次嘗試,使來自同一位址的並行請求無法鑽過限制。被限流的瀏覽器現在會在登入畫面看到專屬的限流訊息,而不是被告知密碼錯誤;限流也不再像密碼錯誤那樣被記住:等待結束後,下一次嘗試無需重新整理頁面即可再次通過。中途放棄的嘗試——密碼還在驗證時分頁就被關閉——現在會立即釋放其保留的名額,而不是在這一分鐘剩下的時間裡繼續計入該位址;登入成功也只釋放自己的保留,而不再清空該位址的全部紀錄:在共享網路位址背後,某人正確登入不再重設攻擊者的嘗試額度,已記錄的失敗只隨其所在的一分鐘過期。

- **磁碟上與記錄中的機密獲得更謹慎的處理。** 保存配對狀態的檔案與端對端加密金鑰現在從建立那一刻起就僅擁有者可讀,而不是先寫入再收緊權限;存有密碼雜湊的工作階段資料庫同樣僅限擁有者存取。無介面 `--serve` 不再把配對連結中長期有效的機密列印到記錄:當輸出不是終端機時,連結會被隱藏,只顯示一則提示;`--print-pairing` 可明確恢復原行為。裝置註冊表上限為 32 筆,名稱長度受限,已配對用戶端無法讓儲存檔案無限膨脹;儲存撤銷或新連結失敗時,錯誤現在會回傳給呼叫方,而不是只留在記錄裡。自動啟動不再取代已手動啟動的伺服器,過期的自動啟動錯誤在您自行停止伺服器後即會消失。

### 修正

- **現在也可以在 Electron 外殼中管理配對。** 產生配對連結、列出已配對裝置和撤銷裝置先前只以桌面（Tauri）命令的形式存在；Electron 外殼和瀏覽器用戶端使用的 WebSocket 分派器會回應 "Unknown command"，導致遠端存取面板在那裡無法使用。現在這三個命令在兩條傳輸通道上都經過同一套核心函式，兩者不會再產生落差；回歸測試涵蓋了新的分派路徑，包括對一個執行中的本機伺服器實際產生配對連結。

- **內建瀏覽器啟動更快。** 現在，每個瀏覽器分頁都提供一鍵開啟 ChatGPT、Claude、Gemini 和 Google 的捷徑。專案和群組的內容選單也可以直接在工作階段樹的相應位置建立固定瀏覽器頁面。

### 圖片和文件

- **在 macOS 上可靠地貼上圖片路徑。** 當 WebKit 沒有將複製的圖片公開為檔案時，VelaTerm 現在會從系統剪貼簿讀取圖片，並仍將其作為檔案路徑上傳，而不會無聲地退回代理程式原生的圖片預留位置。遠端視窗會一律顯示圖片貼上設定、說明為何必須使用檔案路徑模式，並停用無法使用的原生選項。
- **將圖片貼到原始碼文件。** 原始碼編輯器現在支援貼上剪貼簿圖片。已儲存的 Markdown 文件會把圖片放在文件旁的 `assets/` 目錄中，並插入可攜式 Markdown 圖片語法；未儲存的草稿則會嵌入圖片資料，避免清除暫存檔時遺失。

### 介面

- **內容選單保持可見並準確對準項目。** 在右側邊緣附近開啟的選單會被正確測量和調整位置。對樹狀節點按右鍵時，現在只會醒目提示選單目標而不改變既有選取；群組選單也包含作用於該群組的終端機。
- **更清爽的編輯效果和狀態標籤。** 原始碼文字不再為 HTML 註解等字元序列顯示箭頭狀字型連字；用量百分比會明確標示為已使用；宿主 WebView 無關的原生內容選單也不會再出現在 VelaTerm 自有選單後方。

### 修正

- **Codex 保持在一般終端機歷程中。** 由 VelaTerm 啟動的 Codex 工作階段現在使用行內終端機模式，因此按 Esc 中斷或返回時，不會再切換終端機畫面緩衝區並讓回捲檢視跳到頂端。使用者自己的 Codex 設定不會被修改。
