## v0.1.104 — 2026-08-25

### AI エージェント

- **子タスクのカードに、各エージェントの実際のモデルと、そのエージェントが理解できる強度フラグが並ぶようになりました。** カードはどのエージェントに対しても `--model` と `--effort` で起動引数を組み立てていましたが、推論強度をその書き方で表すのは Claude・Kiro・Antigravity だけです――Grok と Zoo は `--reasoning-effort`、Cline は `--thinking` と呼びます。それ以外のエージェントで強度を選ぶと、CLI が見たこともないフラグを渡すことになり、セッションは起動に失敗していました。フラグ名も値も、各エージェントが自分で持ち寄るようになりました。モデルの選択欄は、各 CLI が答えられる範囲に従います。一覧を出せるもの（OpenCode、Grok、Crush、Antigravity、Cursor、pi、Kiro）には問い合わせて実際の一覧を並べ、決まった組を持つもの（Claude、Codex、Kimi Code）はその組を並べ、残りは期待される書き方の例を添えたテキスト入力欄になります。インストールされていない、あるいはサインインしていないエージェントは、いつまでも回り続けるのではなくその旨を表示します。「デフォルト」を選ぶと、古い値が残ったままになるのではなく、引き継いだ上書きが解除されるようになりました。強度を選んでも、親セッションから引き継いだモデルが外れることはありません。

- **Kimi Code のセッションから起動した子タスクは Kimi Code のままです。** 親のエージェントを引き継ぐ際に参照する一覧から Kimi Code が漏れていたため、その子セッションは黙って既定のエージェントとして戻ってきていました。

### ワークスペース

- **グループを作った後からでも worktree に移せます。** worktree はグループの作成時に選ぶきりで、それ以降は固定でした。考えを変えるには、グループを消して作り直すしかありませんでした。グループを右クリックして "Move to Worktree…" を選ぶと、新しい worktree を作る、既存のものを結びつける、すでに結びついているグループの向き先を変える、のいずれもできます。変わるのはグループ自身だけです。すでに中にあるセッションは作成時のディレクトリのままで――動作中のセッションを、その足元にある別のディレクトリへ移すことはできません――その後に作ったセッションが worktree で始まります。

- **ミラーモードがサイドバーのツリー全体を対象にするようになりました。** これまで共有していたのは選択状態と折りたたんだパネルだけで、検索ボックスとステータス・マーカーのフィルターは各クライアントの手元に留めていました。同期すると調べ物をしている人の邪魔になる、という考えからです。この理屈は逆でした。ミラーとは、両方のウィンドウが同じ状態を持つことであって、片方がもう片方のキー入力を再生することではありません――こちらで有効なフィルターは、あちらでも有効です。実際に人の邪魔をするのは、両側が違うツリーを表示していることの方です。サイドバーの表示は丸ごと相手に伝わるようになりました。分割レイアウト、それぞれの表示の名前、検索文字列、ステータスとマーカーのフィルター、そして各自の折りたたみ状態です。スナップショットの形式はバージョン 2 に上がり、古いバージョンのクライアントは 1 フレームの半分だけを適用するのではなくミラーを停止します。アップグレードをまたいで開いたままのウィンドウがあれば、再読み込みしてください。

### インターフェース

- **macOS でウィンドウを閉じたときも、終了と同じ確認が出ます。** ⌘Q とメニュー項目はアプリ自身の確認を通っていましたが、赤い閉じるボタンはウィンドウをそのまま破棄していました――そのウィンドウこそ、確認ダイアログが載っている WebView です。そのため、確認がまったく出ないか、「ワークスペースを保存」のチェックボックスもなく文言も未翻訳の、簡素なネイティブの代替が出るかのどちらかでした。3 つのプラットフォームすべてで、答えるまでウィンドウを保持するようになりました。

- **「ワークスペースを保存」が既定でオンになり、変えた設定はそのまま残ります。** レイアウトを失う方が、要らないスナップショットが 1 つ残るより高くつくので、チェックを入れた状態から始めます。この設定は忘れられることもありました。データベースへの書き込みが 400ms のデバウンスを挟んでいたため、終了がその間にプロセスを終わらせてしまい、次の起動で古い値と突き合わせて変更が元に戻っていたのです。書き込みは終了前に必ず流し込むようになりました。バックエンドが詰まっても確認ボタンが回り続けないよう、600ms の上限を設けています。（FarhadGSRX さんによる貢献です。）

- **リモート接続パネルのパスワードを表示できます。** URL のパスワードと SSH のパスワードのどちらにも目のボタンが付き、伏せ字と平文を切り替えられます。表示するかどうかはその入力欄だけの状態で、パネルを閉じるとリセットされるため、パスワードが画面に出たまま残ることはありません。

- **サイドバーのフィルターバッジが、有効なフィルターをすべて数えるようになりました。** マーカーのフィルターはボタンを光らせるだけで数に入っていなかったため、2 つ有効でもバッジが 1 と表示されることがありました。ステータスとマーカーを合わせて数え、ドロップダウンのチェックと一致するようになりました。ステータスのフィルターが 1 つだけのときは、これまでどおり色付きの点が出ます。

### 修正

- **macOS の自動更新がまた動くようになりました。** v0.1.103 のパッケージには AppleDouble の随伴エントリ（`._VelaTerm.app`）が入っていました。アップデーターはパスの先頭要素を取り除くため、これが空のパスになり、アーカイブの展開そのものを拒否していました。両方のアーキテクチャが影響を受けたので、v0.1.103 の macOS ユーザーは全員そこで足止めされていました。パッケージングがこれらのエントリを書き込まないようにしました。

## v0.1.102 — 2026-08-23

### AI エージェント

- **エージェントプリセット――互換性のある CLI を並べて使えます。** これまでエージェントの種類は 1 つの実行ファイルに固定されていたため、フォーク版やナイトリービルド、同じプロトコルを話す別の CLI を追加する手立てがありませんでした。既存の種類の起動引数を書き換えるしかなく、そうすると元の設定は失われます。プリセットは実行ファイル・アイコン・起動引数を自分で持つようになり、新規セッションのメニューに組み込みの種類と並んで表示されます。セッションはどのプリセットから作られたかを記録するため、フォークしても同じ実行ファイルが使われます。デスクトップで作ったプリセットは、ペアリング済みのブラウザやリモートクライアントにもアイコンごと現れます。アイコンは 1 台のマシン上のパスではなくデータとして送られるからです。既存のセッションには手を触れません。以前のバージョンのデータベースも、これまでとまったく同じように起動します。

- **子タスクの確認カードでモデルと推論強度を選べるようになり、どれか 1 つで答えれば全体に反映されます。** エージェントが子タスクの起動を求めてきたとき、確認カードにモデルの選択と――エージェントが対応していれば――推論強度の選択が並ぶようになりました。どちらも親セッション自身の起動引数から埋まっているので、ふだんはクリック 1 回で済みます。カードのエージェントを切り替えると両方を導出し直すため、ある CLI のモデル名が別の CLI のコマンドラインに紛れ込むことはなくなりました。カードは接続中のすべてのクライアントに表示され、どれか 1 つで答えると残りからは消えます。最初の回答がサーバー側でそのタスクを確保するため、スマートフォンとデスクトップで同じ 1 秒のうちに確認しても、worktree と子セッションは 2 つではなく 1 つだけ作られます。

### ワークスペース

- **ミラーモード――すべてのクライアントで同じレイアウトを共有します。** ターミナルの出力はもともと共有されていました（PTY は 1 つ、バイトストリームも 1 本です）。しかしその周りの配置は各クライアントのブラウザストレージにしかなく、LAN 経由で開いたブラウザは自分だけのタブと分割を表示し、片方の画面を並べ替えても、もう片方は何も変わりませんでした。ミラーモードを有効にすると、タブ、分割、アクティブなセッション、サイドバーの選択、折りたたんだパネルがすべてのクライアントに配信され、全員がそれに追従します。切り替えはホスト側のリモートアクセスパネルで操作します。どちら側で並べ替えても相手に反映されます。このウィンドウのレイアウトから外れたセッションは、終了ではなく切り離されるため、相手に追従したせいで誰かのプロセスが止まることはありません。相手のレイアウトを適用しても、手元で入力している人からキーボードを奪うことはありません。スマートフォンはこの対象外です。スマートフォンの 2 階層ナビゲーションはそもそも形の違う UI で、デスクトップの分割ツリーをそのまま持ち込んでも誰の役にも立ちません。

- **右サイドバーの Git タブが、実用的な Git クライアントになりました。** これまでは変更されたファイルを一覧するだけでした。今はファイル単位でもグループ単位でもステージング・ステージ解除ができ、変更の破棄、コミットの作成（amend にも対応）、コミット履歴と各コミットのファイル・差分の表示までこなします。一覧はステージ済み・変更あり・未追跡・コミット済みのセクションに分かれ、それぞれ折りたためます。パスはリポジトリのルートを基準に扱うようになったため、サブディレクトリで開いたセッションでも表示どおりのファイルが対象になり、detached HEAD の状態は HEAD という名前のブランチとしてではなく、そのまま detached HEAD と表示されます。

### インターフェース

- **⌘Q でも、ウィンドウを閉じたときと同じ確認が出ます。** アプリケーションメニューの終了項目はシステム標準のもので、プロセスをそのまま終了させていました。そのため ⌘Q を押すと、閉じるボタンでは表示される「ワークスペースを保存しますか」の確認が飛ばされ、同じつもりの操作が、やり方によって違う結果になっていました。どちらの経路も 1 つの確認を通るようになりました。確認を表示するウィンドウがその間に再読み込みされたりクラッシュしたりしていた場合は、もう一度 ⌘Q を押すと確認をやり直し、それでも駄目ならネイティブのダイアログに切り替えます。アプリが終了できなくなることはありません。

- **ショートカットの表示が、実際に効くキーと一致するようになりました。** 既定のキーはプラットフォームごとに違い、ブラウザは ⌘/Ctrl と文字の組み合わせを自分のために予約しています――⌘D はブックマーク、⌘T は新しいタブ。そのため macOS では、VelaTerm を URL で開くとアプリ自身の ⌘ ショートカットがページまで届きませんでした。通常のブラウザタブでは、どの OS でも Ctrl+Alt の割り当てを使うようになり、デスクトップアプリとリモート接続ウィンドウは ⌘ のままです。ツールチップと空のタブに出るヒントは、ハードコードされた ⌘ の組み合わせではなく、実際に有効な割り当て――自分で変更したものも含めて――を表示します。ターミナルが遮るのはアプリが実際に使っている組み合わせだけなので、操作の割り当てを変えれば、そのキーの扱いも一緒に移ります。

- **フォントのプリセットが Nerd Font と CJK に対応し、インストールされていないフォントを指定するとその旨が表示されます。** プリセット一覧に、よく使われる Nerd Font と CJK のフォントファミリーが加わりました。手で入力したフォント名はそのまま表示したうえで確認され、システムに存在しない場合は、指定とは似ても似つかない既定のフォントに黙って戻すのではなく、設定ページにその旨が表示されます。

- **macOS のテキスト入力欄が、入力した文字を勝手に大文字化・修正しなくなりました。** システムの自動大文字化・自動修正・スペルチェックがアプリ内のすべての入力欄に効いていて、セッション名やコマンドの入力欄でも「npm」が「Npm」になっていました。すべての入力欄でこれらを無効にしました。

### Windows

- **中国語・日本語・韓国語の入力で、変換中の文字と候補ウィンドウがまた表示されるようになりました。** どちらも見えない状態で、手探りで入力して Enter を押すまで結果が分かりませんでした。原因は自分たちの CSS 2 か所です。変換中の文字を載せるオーバーレイの入れ物が幅ゼロに潰れており、オーバーレイの `right` はその中でどこも指さない値になっていました。候補ウィンドウは OS がオーバーレイの矩形を基準に位置を決めるため、これに巻き込まれていました。オーバーレイはふたたび描画され、アプリのテーマの色が付くようになりました。その土台になっている見えない入力要素も、変換が終わると領域を手放すため、その部分をクリックしたりドラッグしたりしても、これまでのように空の要素に覆われることなく、ターミナルまで届きます。

- **ネイティブのタイトルバーがライト／ダークの設定に追従します。** このアプリはシステムのタイトルバーをそのまま使いますが、Windows は指示がない限りタイトルバーをライトで描くため、ダークの画面の上に白い帯が乗っていました。タイトルバーがアプリの見た目に合うようになり、SSH やリモート接続のウィンドウなど、後から開くウィンドウにも適用されます。「システムに合わせる」を選んだ場合は、値を固定せず OS に制御を戻します。

- **起動直後に現れる小さな四角が出なくなりました。** 多重起動を防ぐプラグインが隠しメッセージウィンドウを作りますが、そのスタイルが約束している透明化を実際には行っていませんでした。そのため Windows がサイズゼロのウィンドウを最小サイズまで広げ、起動中に小さな四角を描くことがありました。これを正しく透明にしました。多重起動の防止そのものの動作は変わりません。

### パフォーマンス

- **リモートアクセスの初回表示までの読み込みが大幅に減りました。** 静的アセットは必要に応じて圧縮して配信し、キャッシュ検証用の情報を付けるようになったため、2 回目以降のアクセスは再ダウンロードではなく再検証で済みます。言語パックとターミナルのオプション扱いのレンダラーも、最初の転送に含めるのをやめ、必要になったときだけ読み込むようにしました。あわせて、初回の転送量はおよそ 5 分の 1 になりました。

### 修正

- **起動された子セッションが、依頼元のセッションと同じ条件で始まるようになりました。** 子セッションは親の権限モードも起動引数も引き継いでいなかったため、確認をスキップして動いているセッションの子が確認を求めてきたり、親で指定していたモデルが外れたりしていました。どちらも引き継ぐようになり、指定がなければそのエージェント種別の全体設定――「新しいエージェントセッション」のメニューが使うのと同じもの――にフォールバックします。

- **リモートウィンドウの再接続で「認証に失敗しました」と誤って表示されなくなりました。** ウィンドウが再接続する際、新しい WebSocket と置き換えられる側の WebSocket が競合し、負けた方の後始末が認証の失敗として報告されていました。その結果、まったく正常なペアリングが拒否されたかのようなバナーが出ていました。

- **グループを自分自身の配下へドラッグできなくなりました。** グループを自分の子孫の 1 つにドロップすると、その枝がまるごとツリーから外れ、中のセッションがサイドバーから消えて、データベースを手で修復するまで戻りませんでした。この移動は拒否されるようになりました。

- **他のツールから起動しても、エージェントの出力の色が保たれます。** ターミナルは自分を起動したプロセスの環境を引き継ぐため、`NO_COLOR`、`CI`、`FORCE_COLOR=0` を export する IDE やエージェントの実行環境から起動すると、ターミナル自身はフルカラーを名乗っているのに、VelaTerm の中のエージェント TUI がすべて白黒で表示されていました。セッションの開始時に、引き継いだこれらの値を取り除くようにしました。自分の shell の設定ファイルで export した同じ変数はこれまでどおり効きます。その設定ファイルはセッションの中で実行されるからです。

## v0.1.101 — 2026-08-15

### リモートアクセス

- **共有リンクが使うアドレスを選べるようになり、Tailscale のアドレスも表示されます。** アドレス一覧は従来のプライベート IPv4 範囲しか受け付けなかったため、キャリアグレード NAT 範囲(100.64.0.0/10)のアドレスを割り当てる Tailscale などの VPN メッシュは、サーバーがすでにその経路で到達可能だったにもかかわらず、リモートアクセスパネルとペアリングリンクから黙って除外されていました。これらのアドレスが一覧に表示されるようになり、VPN トンネルは既定にならないよう最後に並びます。パネルに追加された IP セレクター(起動前と実行中の両方で表示)は、各候補をインターフェイス名付きで示し、VPN トンネルに印を付けます。アドレスを選ぶとその URL が先頭に移動し、ペアリングリンクがまさにそのホストで再生成されるため、コピーしたリンクは VPN 経由でしかこのマシンに届かない端末でも、URL を手で編集することなくそのまま使えます。ペアリングリンクの下の QR コードはスマートフォンで直接読み取れます。選択は記憶され、選んだインターフェイスが消えた場合は選択を忘れることなく「自動」に戻ります。サーバー自体は変わらず、引き続きすべてのインターフェイスで待ち受けます。サーバー起動後に現れたアドレス(たとえば後から接続した VPN)を選んだ場合、これまでは次回の再起動までペアリングリンクしか追従しませんでしたが、コピーされる URL と QR コードも即座に更新されるようになりました。VPN トンネルはどのプラットフォームでも LAN アドレスの後ろに並び、サーバー停止中に選んだアドレスは起動後の最初のペアリングリンクに使われ、重なり合ったリンク再生成が新しいリンクを古いリンクで上書きすることもなくなりました。

- **共有が再起動後も維持されるようになりました。** これまでペアリングトークンはサーバーの起動のたびに再生成されていたため、VelaTerm を終了して開き直すと共有済みのリンクはすべて静かに無効になり、どの端末もペアリングをやり直す必要がありました。トークン、ペアリング済み端末、端末のブロックリストは、データディレクトリ内の所有者のみが読めるファイルに保存されるようになりました。ペアリング済みの端末は再起動後も保存された URL でそのまま再接続でき（アクセスパスワードは引き続き必須の第 2 要素です）、ブロックした端末はブロックされたままです。さらに VelaTerm は共有が有効だったことを記憶します。サーバーが動作したままアプリを終了すると、次回の起動時に同じポートで自動的に再開されます — デスクトップアプリでも、`--serve` で動く GUI なしのサーバーでも同様です。自分で停止した場合は、次回何も自動起動しません。ポートが使用中などの理由で自動起動に失敗しても、アプリは通常どおり起動し、リモートアクセスパネルに原因が表示されます。ポート欄は既定値に戻らず、実際に使ったポートを記憶するようになりました。「リンクを再生成」は引き続き明示的な無効化手段です。即座に新しいトークンを発行し、古いリンクをすべて無効にして、保存された状態を上書きします。アクセスパスワード自体がディスクに書き込まれることはなく、保存されるのはメモリハードなハッシュ（Argon2id）のみです。

### セキュリティ

- **ペアリング済みデバイスから共有そのものを管理できなくなりました。** これまで、ペアリング済みのブラウザはデスクトップアプリと同じ管理コマンドを呼び出せました――新しいペアリングリンクの作成(デバイスのブロックリストも消去されます)、他のデバイスの一覧表示や取り消し、サーバーの停止や再設定など。さらに設定ストアは、アクセスパスワードのメモリハードなハッシュや、次回起動時に読み込まれる自動開始の設定を含む設定一式をどのクライアントにも渡していました。管理コマンドは今後デスクトップアプリと Electron シェル専用になり、設定 API はペアリング済みデバイスからの読み取りでリモートアクセス関連のキーと Gitea トークンを除外し、それらへの書き込みを拒否します。ペアリング済みデバイスは本来の役割――ターミナルセッションと完全なシェルアクセス――をそのまま保ちますが、パスワードの検証値を読むことも、他のデバイスを招き入れたり追い出したりすることも、次回起動が使うポートを書き換えることもできなくなりました。保存されたシークレットを読み書き・削除するコマンド — Gitea トークンや記憶されたホストのパスワード — もペアリング済みデバイスからは拒否されるようになり、パスを受け取るコマンド――読み取り、プレビュー、書き込み、作成、名前変更、削除、さらにファイルの git 差分表示やリポジトリのクローン先フォルダーの指定――は、シンボリックリンクを先に解決したうえで、ペアリング状態や鍵が置かれている VelaTerm 自身のデータディレクトリ内のパスを拒否します。それ以外のパスは従来どおり機能するため、リモートでのファイル閲覧・編集はそのまま使えます。パスを受け取るすべてのリモートコマンドをテストが列挙するため、新しいコマンドが気づかれずにこのチェックをすり抜けることはできません。これらの保護がリクエストを拒否した場合、ブラウザには生の英語エラーではなく、きちんと翻訳されたメッセージが表示されます。

- **取り消しやリンクの再生成が、二重インスタンス構成でも失われなくなりました。** 自動開始を有効にしたヘッドレスの `--serve` サーバーでは、2 つのサーバーインスタンスがそれぞれ保存済みペアリング状態のコピーを持ち、全体を書き戻していたため、一方で行った取り消しや新しいペアリングリンクがもう一方に静かに巻き戻されることがありました。同じプロセス内のすべてのインスタンスは、データディレクトリごとに単一のペアリング状態を共有するようになりました。取り消しとローテーションは即座にすべてに反映され、ファイルへの書き込みはちょうど 1 か所に集約されます。ファイルは本当の再起動をまたぐ正となるデータのままです。

- **失敗したログインの繰り返しは抑制されます。** アクセスパスワードの検証には意図的に計算コストの高い Argon2id を使っており、ポートに到達できる相手なら誰でも試行できます。同じアドレスから 5 回失敗すると、以降の試行はハッシュ計算が始まる前に 1 分間拒否されます。ハッシュ計算自体もサーバーのイベントループの外で実行され、同時に走る検証数には固定の上限があります。誤ったパスワードの洪水でサーバーをメモリハードなハッシュ計算で飽和させたり、接続済みデバイスの応答を遅らせたりすることはもうできません。この抑制はメモリ上にあり、サーバーの再起動でリセットされます。実際の防壁はペアリングトークンとパスワードのままです。この制限は同じデータディレクトリを使うすべてのサーバーインスタンスで共有されるようになり、`--serve` の二重インスタンス構成でも試行回数の予算が倍になることはありません。また、パスワード検証が始まる前に試行が予約されるため、同一アドレスからの並列リクエストが制限をすり抜けることもできません。制限中のブラウザには、パスワードが違うという表示ではなく、ログイン画面に専用のレート制限メッセージが表示されます。また、制限は間違ったパスワードのようには記憶されなくなりました。待ち時間が過ぎれば、ページを再読み込みしなくても次の試行が再び通ります。途中で放棄された試行(パスワードの検証中にタブが閉じられた場合)は、残りの 1 分間そのアドレスに数え続けられるのではなく、予約された枠を即座に解放するようになりました。また、ログインに成功しても解放されるのは自分の予約だけで、そのアドレスの記録全体は消去されません。共有ネットワークアドレスの背後では、誰かが正しくログインしても攻撃者の試行予算はリセットされず、記録された失敗はその 1 分が経過して初めて期限切れになります。

- **ディスク上とログの中の秘密情報を、より慎重に扱うようになりました。** ペアリング状態のファイルとエンドツーエンド暗号化の鍵は、最初の書き込み後に制限するのではなく、作成時点から所有者だけが読めるように作られます。パスワードのハッシュを含むセッションデータベースも所有者のみに制限されます。ヘッドレスの `--serve` は、ペアリングリンクの長命な秘密をログに出力しなくなりました。出力先がターミナルでない場合はリンクを伏せて案内を表示し、`--print-pairing` で明示的に元の動作へ戻せます。デバイスレジストリは名前の長さを制限したうえで 32 件までに制限され、ペアリング済みクライアントが保存ファイルを際限なく肥大させることはできません。取り消しや新しいペアリングリンクの保存に失敗した場合、そのエラーはログの 1 行ではなく呼び出し元に届きます。自動開始は手動で起動済みのサーバーを置き換えなくなり、古い自動開始のエラーはサーバーを自分で停止すると消えます。

### 修正

- **ターミナルから起動したプログラムが AppImage 自身の環境を引き継がなくなりました（Linux）。** AppImage のランチャーは `PYTHONHOME`、`PYTHONPATH`、`PERLLIB`、`QT_PLUGIN_PATH` と GStreamer のプラグインパスをバンドルの一時マウントディレクトリへ向け、`PATH` と `LD_LIBRARY_PATH` の先頭にもバンドル内のディレクトリを差し込みます。ターミナルは自分の環境をそのまま起動する shell へ渡すため、システムの `python3` が標準ライブラリをバンドル内に探しに行って起動すらできず、動的リンクされた他のプログラムもシステム側ではなくバンドル内のライブラリを読み込んでいました。VelaTerm は shell や外部ツールを起動する前にこれらのバンドル由来のパスを取り除き、利用者自身が設定した値には手を触れません。`APPDIR` と `APPIMAGE` は残るため、AppImage から動いているかを確認するプログラムはこれまでどおり判定できます。影響を受けるのは AppImage 版だけで、deb パッケージ、macOS、Windows の動作は変わりません。

- **バックグラウンドセッションをより明確に管理。** メニューに各セッションの状態を表示し、上限超過ダイアログでは複数タブをまとめて終了できます。
- **安全な終了と多言語更新ノート。** 実行中セッションを停止する前に終了確認を表示し、Codex lifecycle の正確な ID を優先します。自動更新ノートは全組み込み言語に対応しました。

### 画像とドキュメント

- **macOS で画像パスを確実に貼り付け。** WebKit がコピーされた画像をファイルとして公開しない場合でも、VelaTerm がネイティブクリップボードから画像を読み取り、エージェント固有の画像プレースホルダーへ暗黙にフォールバックせず、ファイルパスとしてアップロードするようになりました。リモートウィンドウでは画像貼り付け設定を常に表示し、ファイルパスモードが必要な理由を説明して、利用できないネイティブオプションを無効にします。
- **ソースドキュメントへ画像を貼り付け。** ソースエディタがクリップボード画像に対応しました。保存済みの Markdown ドキュメントでは、画像をドキュメント横の `assets/` に保存して移植可能な Markdown 画像構文を挿入します。未保存の下書きでは画像データを埋め込み、一時ファイルの削除時にも失われないようにします。

### インターフェース

- **コンテキストメニューを常に表示し、正しい項目を対象に。** 右端付近で開くメニューの寸法と位置が正しく調整されるようになりました。ツリーノードを右クリックしても既存の選択は変えず、メニュー対象だけを強調表示します。グループメニューには、そのグループを対象とするターミナルも追加されました。
- **編集表示とステータスラベルを整理。** ソーステキストでは HTML コメントなどの文字列に矢印状のフォント合字を表示しなくなりました。使用率には「使用済み」であることを明記し、ホスト WebView の無関係なネイティブコンテキストメニューが VelaTerm のメニュー背後に表示される問題も解消しました。

### 修正

- **Codex が通常のターミナル履歴に留まるように。** VelaTerm から起動した Codex セッションはインラインターミナルモードを使用するようになりました。Esc で中断または戻ったときに画面バッファが切り替わり、スクロールバック表示が先頭へ飛ぶことはありません。ユーザー自身の Codex 設定は変更されません。
