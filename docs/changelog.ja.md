## v0.1.106 — 2026-09-02

### ワークスペース

- **サイドバーに「コレクション」を追加：ディスク上のフォルダーに紐づかない最上位コンテナ。** リモートセッションやブラウザページ、一時的なコマンド実行用のターミナルなど、特定のリポジトリに属さないセッションがあります。これまではそうしたセッションもプロジェクト内に置くしかなく、管理しづらい状態でした。コレクションは、ディスク上の実フォルダーを持たない、名前付きの独立した項目です。プロジェクトルートが存在しないため、無関係な操作はクリック後にエラーになるのではなく、最初から非表示になります。「New Worktree Session」や「Move to Worktree…」、新規セッションダイアログのワークツリー選択機能などは、コレクション内では非表示になります。その代わり、新規セッションダイアログにはホームディレクトリをデフォルトとする作業ディレクトリ（Working directory）入力欄が用意され、デスクトップ版ではネイティブのフォルダー選択ダイアログも利用できます。また、ディレクトリを指定せずに開始したセッションは、アプリの起動パス（macOS では `/`）を引き継ぐのではなく、ホームディレクトリから開始するようになりました。

- **リソースパネルに対象セッションだけでなくマシン全体の状況を表示。** 以前はセッション自身のプロセスツリーの CPU とメモリしか表示されず、そのセッションがリソースを消費し尽くしているのか、マシン自体がすでに過負荷なのかを判別できませんでした。今回の更新で、パネルが「THIS SESSION」と「SYSTEM」に分割されました。「SYSTEM」セクションには CPU、メモリ、スワップのプログレスバーが表示され（70% を超えると黄色、90% を超えると赤色に変化）、プラットフォーム固有の情報も 1 行表示されます。macOS ではメモリプレッシャー、Linux ではコア数で正規化されたロードアベレージが表示され、同等の指標がない Windows では何も表示されません。現在のセッション情報のみを確認したい場合は、パネルヘッダーの「system」のチェックを外すことでシステム行を非表示にし、バックグラウンドでのサンプリング処理も完全に停止できます。この設定は保存され、すべてのセッションのパネルに適用されます。

- **Windows と Linux に Alt キーでアクセスできるメニューバーを追加。** macOS にはネイティブのシステムメニューがありますが、Windows と Linux では、設定、アップデート確認、ペイン分割などの操作はタイトルバーのアイコンからしか利用できませんでした。今回、Alt キーを単体で押して離すことで、メニューバーの表示／非表示を切り替えられるようになりました。Alt キーを組み合わせた通常のショートカットはそのまま動作します。ターミナル内では Alt キーが Meta プレフィックスとして機能するため、Alt+B や Alt+F などのショートカットは引き続きシェルへ直接送信され、ターミナルに何も送信しない単体の Alt キー入力のみがメニューバーを起動します。メニューバーには「File」（設定、アップデート確認）、「Terminal」（新規ターミナル、右に分割、下に分割）、「Help」（ウェブサイト、フィードバック、共有）が含まれ、カスタムキーバインドに応じたショートカットのヒントも表示されます。マウスとキーボードの両方の操作に対応しており、Esc キーを押すと開いているメニューが閉じてメニューバーが非表示になり、ターミナルにフォーカスが戻ります。

- **メニューの「Clear notification badges」により、消せなくなっていたバッジを消去可能に。** Dock バッジは、未読セッション数と未応答のプロセス起動確認カードの合計をカウントします。しかし、サイドバーの消去ボタンは未読セッションがある場合にしか表示されず、消去対象もそれらのセッションのみでした。そのため、ウィンドウを閉じたりセッションを削除したりして確認カードが描画できなくなり、未応答のプロンプトカードが取り残された場合、Dock バッジに「1」が表示されたまま消せなくなっていました。新設されたメニュー項目を実行すると、すべてのセッションを既読にし、保留中のすべての起動リクエストを拒否として処理した上で、OS のバッジカウントを直接ゼロにリセットします。これは、アプリを再起動しても Dock バッジのカウントが保持される macOS において特に役立ちます。

- **ファイルの読み込みやシステムの待機中にウィンドウがフリーズしなくなりました。** 同期的な Tauri コマンドがメインスレッドで実行されていたため、処理中は UI 全体がフリーズしていました。全 43 個のコマンドを精査したところ、13 個でメインスレッド上の I/O が発生していることが判明しました。具体的には、macOS の通知権限リクエストによる確認待ち（最大 1 分間ブロックされる可能性あり）、長時間実行セッションの録画読み込み（数十 MB を 64 KB 単位で読み取り）、スクリーンショット貼り付け時の直接ディスク書き込み、セッションの作業ディレクトリ取得時の `lsof` 実行などです。これら 13 個の処理はすべてメインスレッド外で実行されるようになりました。なお、キー入力の処理は高速パスのまま維持されており、影響はありません。

### リモートアクセス

- **ホスト側で接続中のリモートクライアントを表示。** セッションミラーリングは双方向で行われるため、リモートクライアント側からホスト側のレイアウトを変更できます。しかし以前は、誰が接続しているかはおろか、接続があるかどうかすらホスト側では把握できませんでした。今回からタイトルバーに「Mirrored by N」バッジが表示されるようになり、クリックすると接続中のクライアント名、IP アドレス、接続日時のリストを確認できます。クライアント名は暗号化ハンドシェイク時に通知されます（指定がない場合は「Unnamed」と表示されます）。

### AI エージェント

- **アカウントの使用状況をセッション単位ではなくマシン単位で取得するように改善。** 利用制限はアカウント単位で管理されるものですが、以前は各セッションの情報パネルが個別に制限情報を取得していました。そのため、セッションを 10 個開いていると同一のデータに対して 10 回の重複リクエストが発生し、Claude の厳格なレート制限に引っかかってパネルが空白になることがよくありました。今回の変更で、バックエンドの中央ポーラーが単一のスナップショットを保持し、全セッションがそれを参照するとともに、データ変更時に更新を配信する仕組みに刷新しました。また、不要な権限プロンプトを避けるためシステムキーチェーンにはアクセスせず、`~/.claude`、`~/.codex`、`~/.grok/auth.json` の存在を確認して実際に使用しているプロバイダーのみをポーリングします。スナップショットはディスクに保存されるため、再起動時にも初回ポーリングを待たずにキャッシュされた数値が即座にパネルへ表示されます。また、ノート PC のスリープ復帰時にも次の定期実行を待たずに直ちにデータが更新されます。ポーリングが連続して失敗した場合、バックオフ間隔は最大 8 倍まで自動で延長されます。あわせて設定画面では、分かりにくかった「0 秒」設定を廃止し、更新間隔の入力欄の横に明示的な有効／無効切り替えスイッチを追加しました。

- **使用状況の更新に失敗した際、最新に見せかけるのではなく「stale」と明示。** 以前は更新リクエストが失敗した場合でも、クライアントはキャッシュされたデータを暗黙的に返しつつ、成功したかのように記録していました（タイムスタンプを更新し、エラーをクリアし、バックオフタイマーをリセットしていました）。そのため、実際にはレート制限に達していても、5 分ごとのポーリングを続けながらパネル上は正常に見えてしまっていました。今回の変更により、リクエスト失敗時もキャッシュ値は保持されますが、プロバイダー名の横に黄色の `stale` バッジが表示されるようになりました。バッジにカーソルを合わせると、失敗時刻、エラーの理由、表示中のデータの取得からの経過時間を示すツールチップが表示されます。「Updated」のタイムスタンプは直近で成功した同期時刻を反映し、レート制限されたサーバーからの retry-after 要求にも従うようになりました（手動更新は引き続き即座に実行できます）。

- **使用状況パネルにモデル別の週間クォータを表示。** 使用状況エンドポイントは、アカウント全体での 5 時間および 7 日間の制限に加え、モデル固有の週間クォータも返します。これまではこの情報が活用されておらず、Fable などのモデルを使用しているユーザーは、モデル固有の残り枠ではなくアカウント全体の総使用量しか確認できませんでした。今回の更新により、これらの内訳行が合計値の下にモデルファミリーごとに分類されて表示されるようになりました。

- **OpenCode セッションを再度開いたときにチャット履歴を復元。** 以前はセッションが存在するかどうかを `opencode session list` で確認していましたが、このコマンドは現在の作業ディレクトリ配下のセッションしか取得しませんでした。デスクトップアプリは起動ディレクトリ（macOS では `/`）から実行されるため、既存のセッション ID が見つからず、再開しようとしてもエラーが表示されないまま空白のセッションが開いてしまっていました。今回の修正により、特定のセッション ID を直接問い合わせるようになり、コマンドによって明示的に削除が確認された場合にのみ削除済みとして扱うようになりました。その他のエラー時は判定不能としてセッションの再開処理を進めるため、セッション履歴が誤って失われるのを防ぎます。

### インターフェース

- **IME（入力方式エディタ）での入力中に入力途中のテキストが表示されるようになりました。** これまで、全 3 つのプラットフォームにおいて、IME（かな漢字変換やピンインなど）で入力中のテキストが Enter キーで確定するまで画面に表示されませんでした。これはカスタム CSS ルールが原因でした。xterm は未確定テキストを制約のないオーバーレイコンテナ内に描画しますが、長いターミナル行を折り返すために追加していた `right` 制約によって幅が 0 に計算され、さらに `overflow: hidden` によってテキストが完全に切り取られていました。このルールは削除され、どのテーマとも合わなかったオーバーレイのデフォルト配色（白地に黒）の上書きのみが残されています。また、これに関連する問題も同時に修正されました。xterm は IME 変換候補の位置を合わせるために非表示の textarea をオーバーレイのサイズまで拡張したあと元のサイズに戻さなかったため、その行でマウスクリックやテキスト選択を妨げる不可視のオーバーレイが残ってしまっていました。

- **macOS において、Ctrl ショートカットが Command キーのキーバインドを誤ってトリガーしないように修正。** 以前は macOS 上での修飾キーの判定において Cmd と Ctrl が同一視されていました。その結果、標準的なターミナルショートカットがアプリのキーバインドと衝突し、Ctrl+D（EOF）でペインが分割され、Ctrl+W（単語削除）でペインが閉じられ、Ctrl+F、Ctrl+T、Ctrl+O などのショートカットがアプリに横取りされていました。新しいペインは何の通知もなく起動するため、まるでペインが勝手に出現したように見えていました。今回の修正により、macOS のデスクトップアプリではショートカットに Cmd のみを使用するようになり、他のプラットフォーム（および Mac に接続された Web ブラウザ）では Ctrl のみを使用するようになりました。

- **ドロップダウンメニューで項目を選択した直後に再び開いてしまう問題を修正。** 親の `<label>` 要素が行全体のクリックイベントをトリガーボタンへ伝播させていたため、項目を選択した瞬間にドロップダウンメニューが再度開いてしまっていた問題を修正しました。

### 修正

- **Linux：AppImage が再び起動するようになりました。** 0.1.105 の AppImage は、WebKit のヘルパープロセスを起動できず、Ubuntu 22.04 でウィンドウが表示される前にクラッシュしていました。AppImage のパッケージングツールはバイナリ内のリテラル `/usr` パスを `././` に書き換えるため（インプレースパッチのために文字列の長さを維持する目的）、これらのパスを解決するにはランチャースクリプトで作業ディレクトリを `$APPDIR/usr` に変更する必要があります。0.1.105 では、子シェルへの環境変数の漏洩を防ぐために導入したカスタムランチャースクリプトが環境変数を転送したものの、このディレクトリ変更処理が抜けていました。ランチャーが正しくディレクトリを変更するよう修正し、再発を防ぐためのビルド時アサーションも追加しました。なお、バージョン 0.1.104 以前はこの問題の影響を受けません。

- **Windows：通知音が再び鳴るようになり、通知をクリックして該当セッションへジャンプできるようになりました。** Windows の通知において、macOS 向けのサウンド識別子が通知プラグインに送信されていました。プラグイン側でその識別子名を解析できなかったため無音になっており、設定に関わらず Windows の通知音が一向に鳴らない状態でした。Windows の通知は 2 回前のリリースで生じた問題への回避策としてプラグインを経由させていましたが、その問題は同じリリース内で既に解決されていました。今回の更新でこの迂回処理を取り消し、通知をネイティブチャンネル経由に戻したことで、通知音とクリック時のセッションジャンプ機能の両方が復元されました。

- **Windows：罫線素片とブロック要素のズレを解消。** ターミナルの枠線がプロポーショナルなフォールバックフォントでレンダリングされ、表示の乱れが生じていました。これに対処した後も、フォールバックフォントがメインのターミナルフォントよりもわずかに狭かったため、ブロック要素（プログレスバーや Claude Code のマスコットなどで使用）の各セルの右端に極細の垂直方向の隙間ができていました。今回の修正により、両方の文字範囲を同梱された JetBrains Mono のサブセットから描画することで、グリフの幅が完全に一致するようになりました。

- **Windows：完全版 Git Bash 環境で `git` が正常に動作するよう修正。** 完全版の Git Bash を正常にインストールしていても、ターミナルで `git` を実行すると「command not found」と表示され、完全版 Git Bash のインストールを促すプロンプトが繰り返し表示されていました。Git Bash はどのディレクトリツリーで実行されているかを指定された場合にのみ `mingw64/bin` を `PATH` に追加します。シェルランチャーでこのパラメータの指定が欠落していたため、そのディレクトリにのみ存在するバイナリ（`git` や `curl` など）が見つかりませんでした。あわせて、ダウンロードプロンプトでデフォルトの 64-bit を決め打ちするのではなく、ホストシステムのアーキテクチャに適合したインストーラーを選択するようになりました。

- **Windows：ワークツリーの削除が正常に動作し、Kiro フックの再インストール時に重複登録されないよう修正。** ワークツリーの削除コマンドが、削除対象のワークツリーディレクトリ内から実行されていました。Windows では実行中のプロセスのカレントワーキングディレクトリを削除できないため、この操作は常に権限エラーで失敗していました。今回の修正で Git コマンドをメインリポジトリのルートから実行するようになりました。さらに、フック検出ロジックがスラッシュ区切りのパスと Windows のバックスラッシュ区切りのパスをそのまま比較していたため、判定に失敗して再インストールするたびに重複したフックエントリが追加されていた問題も修正しました。

## v0.1.105 — 2026-08-26

### ワークスペース

- **セッションの状態、未読の印、そしてセッションがまだ動いているかどうかを、バックエンドが判断するようになりました。すべてのクライアントが同じ答えを見ます。** これまでは各クライアントが、自分がたまたま観測したものからこれらを組み立てていたため、「未読」は実質「このウィンドウで読んでいない」という意味でしかありませんでした。ブラウザでセッションを読んでもデスクトップ側は未読のままで、しかも動的なステータスフィルターがその行を共有の一覧へ押し戻し続けるので、「ステータスを更新」を押しても消せませんでした。ステータスのイベントも、そのクライアント自身がセッションを起動して初めて登録されていたため、つないだばかりのブラウザは自分が開いたセッションにだけ点を表示し、残りには何も表示しませんでした。バックエンドが、セッションごとに正となる記録を 1 つ持つようになりました――エージェント、その状態、プロセスが生きているかどうか、そして未読フラグです。クライアントが接続または再接続したときにはまとめて問い合わせに答え、変化があればそのつど全員に配信します。クライアントは自分が観測したことを報告し、結論はバックエンドが出します。スマートフォンでセッションを読めばデスクトップの印も消え、つないだばかりのブラウザは一度も開いていないセッションについても正しい点を表示します。これまでフロントエンドにあった調停のルールは、その理由とテストごと移りました――一度でも報告のあったフックは、生の出力から推測した結果を締め出します。出力が続いていることをビジーの根拠にできるのは、エージェントを持ち、Codex ではなく、まだ正となる報告が届いていないセッションだけです。そして 1200ms の保持時間が、始まったばかりのタスクを、すぐ後ろから届く終了イベントに打ち消されないよう守ります。例外は画面の読み取りです。これには描画済みのグリッドが要り、それはクライアントにしか存在しません。ターミナルのサイズを持っているクライアントが読み取った内容を報告し、それを受け入れるかどうかをバックエンドが決めます――ほかのクライアントからの報告は拒否されます。もしこのあたりで不具合が出た場合は、localStorage の `vlx-arbitration` に `frontend` を設定すると、調停が従来のフロントエンド側の仕組みに戻ります。

- **セッションを再起動しても、もう一方のクライアントでタブが閉じられなくなりました。** `pty://killed` には付随する情報が何もなかったため、受け取った側は再起動と終了を区別できませんでした。すべて終了として扱ってペインを取り除き、そのレイアウトをそのまま相手にも反映していたのです。このイベントは、どのクライアントがなぜプロセスを終わらせたのかを伝えるようになり、再起動であればペインを残したまま新しいプロセスの到着を待ちます。理由が無い、あるいは知らない理由だった場合は、これまでどおり終了として扱います――二度と戻ってこないセッションのペインを開いたままにすると、死んだターミナルが画面に居座ることになり、再起動しようとしていたペインを閉じてしまうより厄介だからです。

- **ワークスペースを復元したばかりのデスクトップにブラウザがつないでも、すべてのセッションが本当に起動されることはなくなりました。** ワークスペースの復元は、プロセスを起動する代わりにプレースホルダーのカードを描きますが、その判断はデスクトップ側にしかありませんでした。ブラウザは相手から届いたレイアウトに従うだけで、「動いていない」と「動いているが、ここでは一度も開いていない」を区別できず、ターミナルをマウントしてしまいます――そしてマウントするとは、起動することです。他人のレイアウトに乗って現れた葉ノードは、その裏にプロセスが無いとバックエンドが答えた場合、プレースホルダーを描くようになりました。自分でセッションを開く操作は、これまでどおり起動する意思とみなします。また、いま見ているターミナルは、プロセスが終了してもカードに置き換わることはありません――そこに出力されたものを、まだ読みたいかもしれないからです。

- **設定の変更が、ほかのクライアントにすぐ届きます。** 正となる設定はもともとバックエンドが持っていましたが、変更しても誰にも知らせていなかったため、もう一方のクライアントが気づくのは次の起動時でした。リモート接続では、これは表示のずれでは済みません。片方のクライアントで「ステータスフィルターを動的に広げる」を切っても、別のクライアントが共有の一覧に行を足し続ければ何の意味もなく、ライブタブの上限が小さいクライアントが、ほかの全員の背後でバックグラウンドのタブを追い出してしまいます。設定を書き込むと、どのキーが変わったかを配信するようになり、各クライアントは起動時と同じ経路でそれを読み直します。したがって、保護された値をリモートの呼び出し元から隠すルールもそのまま働きます――配信されるのはキーの名前だけで、値は決して含まれません。これまで設定を送りも受け取りもしなかったスマートフォンも、この仕組みに加わりました。

- **ブラウザは、自分のレイアウトを復元する前にミラーされたレイアウトを待ちます。** リモートのウィンドウにはレイアウトの出どころが 2 つあります――自分の localStorage にあるものと、ミラーモードでホストから届くものです。そして先に着いた方が、後から来た方に上書きされていました。手元のものを先に描くと、ちらつき以上の代償があります。ターミナルの葉ノードをマウントすることは実際のプロセスを起動することなので、プロセスがすでに無いセッションについては、誰も見ることのない shell を起こしてしまいます。しかもそれは残り続けます。ブラウザはターミナルを終了させず、切り離すだけだからです。ブラウザは、最初の同期が落ち着くまで――最大 2 秒――何も復元せずに待つようになりました。バックエンドが遅い、あるいは届かない場合は、空のウィンドウのまま座り込むのではなく手元のレイアウトに戻ります。スマートフォンと、ミラーを切っているクライアントは、待たずにそのまま進みます。

### リモートアクセス

- **SSH 接続で、自分が起動するサービスのミラーモードを有効にできます。** この切り替えはリモートアクセスパネルにありますが、SSH は向こう側のマシンで GUI なしのサービスを起動するため、そこにはクリックするパネルがありません。Option を押しながら "Connect remote" をクリックすると、SSH のフォームに "Mirror UI across clients" のチェックボックスが現れます（既定はオフです）。この値は接続とともに運ばれ、向こう側のマシンのデータベースには書かず、サービスのメモリ上に保持されます。リモートのデスクトップが持つデータベースをそのまま使う場合に、SSH 接続 1 回で誰かのパネルのスイッチが黙って切り替わるべきではないからです。選んだ内容はホストごとに記憶されるので、履歴から同じマシンを選べばそのまま復元されます。すでに動いているサービスを再利用する条件に、バージョンとデータの扱いに加えてミラーモードも一致することが必要になりました――3 つのうちどれかが違えば古いサービスは置き換えられ、その上で動いていたセッションは終わります。そのため、この項目はデータベースの切り替えと並んで Option の下に置いています。

- **ミラーされている側のクライアントは、そうと分かるようになりました。** 追従している側では、タブや分割が勝手に並び替わるのに、その変化がどこから来たのかを説明するものが画面に何もありませんでした。タイトルバーに Mirrored のバッジが出るようになり、カーソルを乗せると説明が表示されます。ホスト側には出ません――スイッチを持っているのはそちらだからです。

- **手元のマシンとターミナルが動いているマシンとの間でファイルをやり取りできるようになりました。** リモートアクセスでは相手側のファイルを見ることはできても、持ち帰る手段も置いてくる手段もなく、ターミナルでコマンドを打つしかありませんでした。ファイルパネルのコンテキストメニューにダウンロード、ヘッダーにアップロードが加わり、デスクトップからフォルダーの行へファイルをドラッグしても送れます。どちらの方向も他の機能と同じ認証済み接続を通るため、ローカルネットワークのブラウザーからでも、スマートフォンからでも、リモート接続ウィンドウからでも同じように使えます。転送は分割して進み、ツリーの下の一覧に進捗が出ます。別のパネルを見ている間も転送は続きます。ダウンロードはごく普通のダウンロードリンクで、処理はブラウザー自身のダウンロードマネージャーが行います。ディスクへ流し込みながら保存し、速度と残り時間を表示し、一時停止と再開もできます。ファイルの大きさを問わず、どのブラウザーでも、スマートフォンでも同じです。リンクにはそのファイル 1 つのために発行され数分で失効するチケットが載っています。このサーバーは資格情報をヘッダーで扱いますが、リンクをたどるブラウザーはヘッダーを送らないためです。アップロードはまず一時的な名前で書き込み、すべて転送し終えてから正式な名前に変更するので、途中で中断しても中途半端なファイルが残ることはありません。同名のファイルがすでにある場合は、転送を始める前に拒否します。アップロードは速度と残り時間を表示し、接続が切れても終わりにはなりません。失敗したブロックは間隔を空けながら約 1 分間再試行し、そのつど「一時ファイルが実際どこまで届いているか」をサーバーに尋ねます。すでに書き込まれたかもしれないブロックを送り直したりはしません。あきらめた場合もそのバイト列は残ります。同じファイルを同じフォルダーにもう一度ドラッグすれば続きから再開し、再読み込み後でも同じです。途中のファイルを捨てるのはキャンセルしたときだけです。

### AI エージェント

- **Antigravity と Copilot のセッションが、最初のメッセージから名前を付けられるようになりました。** どちらも自動の名前付けから漏れていたため、サイドバーに「Antigravity 1, 2, 3」という行が並んでいました。Antigravity のフックイベントにはユーザーの文章がまったく含まれず、会話 ID とトランスクリプトのパスだけが入っているので、最初のメッセージはトランスクリプトから読み取るようにしました。その後ろに続くメタデータのかたまりは、タイトルには入れません。Copilot のイベントにはイベント名すら無く、形で見分けるしかないため、プロンプトがあってツール名が無い本文を送信とみなすようにしました。これで、セッションの起動時に渡すプロンプトやツールの呼び出しは、正しくタイトルから外れます。

- **Antigravity のセッションを開き直すと、履歴も一緒に戻ります。** 再開には会話 ID が要りますが、起動引数からセッション ID を取り出すパーサーが Antigravity の書き方を認識していませんでした。そのため `--conversation=<id>` は指し示す先を持てず、開き直したセッションはすべて空の状態で立ち上がっていました。

- **`vspawn --yes` は、確認カードを出さずにセッションを起動します。** 「起動前に確認する」を有効にしている人は、1 回の実行で生まれる子セッションのたびにカードをクリックして進める必要がありました。このフラグ――`-y` や `--no-confirm` とも書けます――は、その呼び出しに限ってカードを飛ばし、既定の設定でセッションを開始します。設定そのものは変えないので、次にフラグ無しで起動すればまた確認されます。

- **子タスクのカードのモデル欄に、好きな文字列を入力できます。** これまでは普通のドロップダウンだったため、一覧にあるモデルしか選べませんでした。しかしエージェントが理解できる識別子はそれよりずっと多く、`claude-opus-4-6` のような日付入りの名前、ベンダー名を前に付けた名前、手元で設定したエイリアスなどがあります。この欄はテキスト入力になり、既知のモデルは隣のドロップダウンにショートカットとしてぶら下がる形になりました。一覧はあくまで候補であって、許可リストではありません。入力した文字列がそのまま渡され、空欄なら `--model` 自体を付けず、一覧は入力に応じて絞り込まれ、独自の識別子でどれにも当たらなくなると畳まれます。

### インターフェース

- **ドロップダウンを 1 つにまとめ、どこでもそれを使うようにしました。** アプリのあちこちにあるドロップダウンは、同じコードから十数回コピーされたあと、少しずつ食い違っていきました――パネルの背景が 3 種類、影が 4 種類、ホバーの色が 3 種類、トリガーの高さが 26・28・32 ピクセル、そして複数選択の一覧にしか要らないチェックが、選択中の行に付いていました。1 つのコンポーネントが、マージ時のブランチ選択、設定の言語・既定の shell・フォントの選択、エージェントの選択、worktree のダイアログ、新規セッションと復元したセッションのエージェント種別、そしてフォームのモーダルに最後まで残っていたネイティブの select を、まとめて支えるようになりました。あわせて、どれにも無かったキーボード操作も付きます――矢印キーで移動、Enter で決定、Escape で背後のダイアログを閉じずにドロップダウンだけを閉じ、Home と End で端まで飛べます。ステータスバーにある 2 つのメニューは従来どおりで、サイドバーのステータスフィルターはチェックを残しています。あちらは本当に複数選択だからです。

- **リモートアクセスパネルのパスワード欄を表示できます。** ただのパスワード入力欄だったため、入力した内容を目で確かめられませんでした。目のボタンは存在していましたが、接続パネル自身のファイルの中にしかありませんでした。どちらも 1 つのコンポーネントを共有するようになり、表示するかどうかはパネルを閉じるとリセットされます。

- **IP の選択欄が、システムのコントロールに見えなくなりました。** ネイティブの select だったため、WKWebView がシステム標準の見た目をかぶせ、暗いパネルの上では浮いていました――上で置き換えたドロップダウンとまったく同じ問題です。共有のコンポーネントを使うようになり、ラベルも "IP" だけに短くしました。隣の文章がすでに用途を説明しているからです。

### 修正

- **更新の確認が、毎回きちんとサーバーに問い合わせるようになりました。** 起動したままのクライアントは、最初に見つけたバージョンに固定されていました。0.1.101 を見つけたクライアントは、0.1.104 が出た後も 0.1.101 を案内し続け、「更新を確認」を押しても同じダイアログが開き直すだけでした。以前のコードが、通知がすでに出ている場合はそこで処理を打ち切っていたためです。確認のたびに本当のリクエストを送るようになりました。新しいバージョンが見つかれば画面の通知を差し替え、同じバージョンやダウンロード中の場合はそのままにし、サーバーが更新は無いと答えた場合は古くなった通知を取り下げます――そのバージョンが取り下げられたか、その間に自分で入れたか、どちらかだからです。「手動でダウンロード」のボタンは、ウェブサイトのダウンロードページを開くようになりました。これまではアップデーター自身のパッケージを渡していましたが、あれはその場で展開される形式で、手でインストールすることはできません。

## v0.1.104 — 2026-08-25

### AI エージェント

- **子タスクのカードに、各エージェントの実際のモデルと、そのエージェントが理解できる強度フラグが並ぶようになりました。** カードはどのエージェントに対しても `--model` と `--effort` で起動引数を組み立てていましたが、推論強度をその書き方で表すのは Claude・Kiro・Antigravity だけです――Grok と Zoo は `--reasoning-effort`、Cline は `--thinking` と呼びます。それ以外のエージェントで強度を選ぶと、CLI が見たこともないフラグを渡すことになり、セッションは起動に失敗していました。フラグ名も値も、各エージェントが自分で持ち寄るようになりました。モデルの選択欄は、各 CLI が答えられる範囲に従います。一覧を出せるもの（OpenCode、Grok、Crush、Antigravity、Cursor、pi、Kiro）には問い合わせて実際の一覧を並べ、決まった組を持つもの（Claude、Codex、Kimi Code）はその組を並べ、残りは期待される書き方の例を添えたテキスト入力欄になります。インストールされていない、あるいはサインインしていないエージェントは、いつまでも回り続けるのではなくその旨を表示します。「デフォルト」を選ぶと、古い値が残ったままになるのではなく、引き継いだ上書きが解除されるようになりました。強度を選んでも、親セッションから引き継いだモデルが外れることはありません。

### ワークスペース

- **グループを作った後からでも worktree に移せます。** worktree はグループの作成時に選ぶきりで、それ以降は固定でした。考えを変えるには、グループを消して作り直すしかありませんでした。グループを右クリックして "Move to Worktree…" を選ぶと、新しい worktree を作る、既存のものを結びつける、すでに結びついているグループの向き先を変える、のいずれもできます。変わるのはグループ自身だけです。すでに中にあるセッションは作成時のディレクトリのままで――動作中のセッションを、その足元にある別のディレクトリへ移すことはできません――その後に作ったセッションが worktree で始まります。

- **ミラーモードがサイドバーのツリー全体を対象にするようになりました。** これまで共有していたのは選択状態と折りたたんだパネルだけで、検索ボックスとステータス・マーカーのフィルターは各クライアントの手元に留めていました。同期すると調べ物をしている人の邪魔になる、という考えからです。この理屈は逆でした。ミラーとは、両方のウィンドウが同じ状態を持つことであって、片方がもう片方のキー入力を再生することではありません――こちらで有効なフィルターは、あちらでも有効です。実際に人の邪魔をするのは、両側が違うツリーを表示していることの方です。サイドバーの表示は丸ごと相手に伝わるようになりました。分割レイアウト、それぞれの表示の名前、検索文字列、ステータスとマーカーのフィルター、そして各自の折りたたみ状態です。スナップショットの形式はバージョン 2 に上がり、古いバージョンのクライアントは 1 フレームの半分だけを適用するのではなくミラーを停止します。アップグレードをまたいで開いたままのウィンドウがあれば、再読み込みしてください。

## v0.1.102 — 2026-08-23

### AI エージェント

- **エージェントプリセット――互換性のある CLI を並べて使えます。** これまでエージェントの種類は 1 つの実行ファイルに固定されていたため、フォーク版やナイトリービルド、同じプロトコルを話す別の CLI を追加する手立てがありませんでした。既存の種類の起動引数を書き換えるしかなく、そうすると元の設定は失われます。プリセットは実行ファイル・アイコン・起動引数を自分で持つようになり、新規セッションのメニューに組み込みの種類と並んで表示されます。セッションはどのプリセットから作られたかを記録するため、フォークしても同じ実行ファイルが使われます。デスクトップで作ったプリセットは、ペアリング済みのブラウザやリモートクライアントにもアイコンごと現れます。アイコンは 1 台のマシン上のパスではなくデータとして送られるからです。既存のセッションには手を触れません。以前のバージョンのデータベースも、これまでとまったく同じように起動します。

- **子タスクの確認カードでモデルと推論強度を選べるようになり、どれか 1 つで答えれば全体に反映されます。** エージェントが子タスクの起動を求めてきたとき、確認カードにモデルの選択と――エージェントが対応していれば――推論強度の選択が並ぶようになりました。どちらも親セッション自身の起動引数から埋まっているので、ふだんはクリック 1 回で済みます。カードのエージェントを切り替えると両方を導出し直すため、ある CLI のモデル名が別の CLI のコマンドラインに紛れ込むことはなくなりました。カードは接続中のすべてのクライアントに表示され、どれか 1 つで答えると残りからは消えます。最初の回答がサーバー側でそのタスクを確保するため、スマートフォンとデスクトップで同じ 1 秒のうちに確認しても、worktree と子セッションは 2 つではなく 1 つだけ作られます。

### ワークスペース

- **ミラーモード――すべてのクライアントで同じレイアウトを共有します。** ターミナルの出力はもともと共有されていました（PTY は 1 つ、バイトストリームも 1 本です）。しかしその周りの配置は各クライアントのブラウザストレージにしかなく、LAN 経由で開いたブラウザは自分だけのタブと分割を表示し、片方の画面を並べ替えても、もう片方は何も変わりませんでした。ミラーモードを有効にすると、タブ、分割、アクティブなセッション、サイドバーの選択、折りたたんだパネルがすべてのクライアントに配信され、全員がそれに追従します。切り替えはホスト側のリモートアクセスパネルで操作します。どちら側で並べ替えても相手に反映されます。このウィンドウのレイアウトから外れたセッションは、終了ではなく切り離されるため、相手に追従したせいで誰かのプロセスが止まることはありません。相手のレイアウトを適用しても、手元で入力している人からキーボードを奪うことはありません。スマートフォンはこの対象外です。スマートフォンの 2 階層ナビゲーションはそもそも形の違う UI で、デスクトップの分割ツリーをそのまま持ち込んでも誰の役にも立ちません。

- **右サイドバーの Git タブが、実用的な Git クライアントになりました。** これまでは変更されたファイルを一覧するだけでした。今はファイル単位でもグループ単位でもステージング・ステージ解除ができ、変更の破棄、コミットの作成（amend にも対応）、コミット履歴と各コミットのファイル・差分の表示までこなします。一覧はステージ済み・変更あり・未追跡・コミット済みのセクションに分かれ、それぞれ折りたためます。パスはリポジトリのルートを基準に扱うようになったため、サブディレクトリで開いたセッションでも表示どおりのファイルが対象になり、detached HEAD の状態は HEAD という名前のブランチとしてではなく、そのまま detached HEAD と表示されます。

### インターフェース

- **⌘Q でも、ウィンドウを閉じたときと同じ確認が出ます。** アプリケーションメニューの終了項目はシステム標準のもので、プロセスをそのまま終了させていました。そのため ⌘Q を押すと、閉じるボタンでは表示される「ワークスペースを保存しますか」の確認が飛ばされ、同じつもりの操作が、やり方によって違う結果になっていました。どちらの経路も 1 つの確認を通るようになりました。確認を表示するウィンドウがその間に再読み込みされたりクラッシュしたりしていた場合は、もう一度 ⌘Q を押すと確認をやり直し、それでも駄目ならネイティブのダイアログに切り替えます。アプリが終了できなくなることはありません。

## v0.1.101 — 2026-08-15

### リモートアクセス

- **共有リンクが使うアドレスを選べるようになり、Tailscale のアドレスも表示されます。** アドレス一覧は従来のプライベート IPv4 範囲しか受け付けなかったため、キャリアグレード NAT 範囲(100.64.0.0/10)のアドレスを割り当てる Tailscale などの VPN メッシュは、サーバーがすでにその経路で到達可能だったにもかかわらず、リモートアクセスパネルとペアリングリンクから黙って除外されていました。これらのアドレスが一覧に表示されるようになり、VPN トンネルは既定にならないよう最後に並びます。パネルに追加された IP セレクター(起動前と実行中の両方で表示)は、各候補をインターフェイス名付きで示し、VPN トンネルに印を付けます。アドレスを選ぶとその URL が先頭に移動し、ペアリングリンクがまさにそのホストで再生成されるため、コピーしたリンクは VPN 経由でしかこのマシンに届かない端末でも、URL を手で編集することなくそのまま使えます。ペアリングリンクの下の QR コードはスマートフォンで直接読み取れます。選択は記憶され、選んだインターフェイスが消えた場合は選択を忘れることなく「自動」に戻ります。サーバー自体は変わらず、引き続きすべてのインターフェイスで待ち受けます。サーバー起動後に現れたアドレス(たとえば後から接続した VPN)を選んだ場合、これまでは次回の再起動までペアリングリンクしか追従しませんでしたが、コピーされる URL と QR コードも即座に更新されるようになりました。VPN トンネルはどのプラットフォームでも LAN アドレスの後ろに並び、サーバー停止中に選んだアドレスは起動後の最初のペアリングリンクに使われ、重なり合ったリンク再生成が新しいリンクを古いリンクで上書きすることもなくなりました。

- **共有が再起動後も維持されるようになりました。** これまでペアリングトークンはサーバーの起動のたびに再生成されていたため、VelaTerm を終了して開き直すと共有済みのリンクはすべて静かに無効になり、どの端末もペアリングをやり直す必要がありました。トークン、ペアリング済み端末、端末のブロックリストは、データディレクトリ内の所有者のみが読めるファイルに保存されるようになりました。ペアリング済みの端末は再起動後も保存された URL でそのまま再接続でき（アクセスパスワードは引き続き必須の第 2 要素です）、ブロックした端末はブロックされたままです。さらに VelaTerm は共有が有効だったことを記憶します。サーバーが動作したままアプリを終了すると、次回の起動時に同じポートで自動的に再開されます — デスクトップアプリでも、`--serve` で動く GUI なしのサーバーでも同様です。自分で停止した場合は、次回何も自動起動しません。ポートが使用中などの理由で自動起動に失敗しても、アプリは通常どおり起動し、リモートアクセスパネルに原因が表示されます。ポート欄は既定値に戻らず、実際に使ったポートを記憶するようになりました。「リンクを再生成」は引き続き明示的な無効化手段です。即座に新しいトークンを発行し、古いリンクをすべて無効にして、保存された状態を上書きします。アクセスパスワード自体がディスクに書き込まれることはなく、保存されるのはメモリハードなハッシュ（Argon2id）のみです。

### セキュリティ

- **ペアリング済みデバイスから共有そのものを管理できなくなりました。** これまで、ペアリング済みのブラウザはデスクトップアプリと同じ管理コマンドを呼び出せました――新しいペアリングリンクの作成(デバイスのブロックリストも消去されます)、他のデバイスの一覧表示や取り消し、サーバーの停止や再設定など。さらに設定ストアは、アクセスパスワードのメモリハードなハッシュや、次回起動時に読み込まれる自動開始の設定を含む設定一式をどのクライアントにも渡していました。管理コマンドは今後デスクトップアプリと Electron シェル専用になり、設定 API はペアリング済みデバイスからの読み取りでリモートアクセス関連のキーと Gitea トークンを除外し、それらへの書き込みを拒否します。ペアリング済みデバイスは本来の役割――ターミナルセッションと完全なシェルアクセス――をそのまま保ちますが、パスワードの検証値を読むことも、他のデバイスを招き入れたり追い出したりすることも、次回起動が使うポートを書き換えることもできなくなりました。保存されたシークレットを読み書き・削除するコマンド — Gitea トークンや記憶されたホストのパスワード — もペアリング済みデバイスからは拒否されるようになり、パスを受け取るコマンド――読み取り、プレビュー、書き込み、作成、名前変更、削除、さらにファイルの git 差分表示やリポジトリのクローン先フォルダーの指定――は、シンボリックリンクを先に解決したうえで、ペアリング状態や鍵が置かれている VelaTerm 自身のデータディレクトリ内のパスを拒否します。それ以外のパスは従来どおり機能するため、リモートでのファイル閲覧・編集はそのまま使えます。パスを受け取るすべてのリモートコマンドをテストが列挙するため、新しいコマンドが気づかれずにこのチェックをすり抜けることはできません。これらの保護がリクエストを拒否した場合、ブラウザには生の英語エラーではなく、きちんと翻訳されたメッセージが表示されます。

- **取り消しやリンクの再生成が、二重インスタンス構成でも失われなくなりました。** 自動開始を有効にしたヘッドレスの `--serve` サーバーでは、2 つのサーバーインスタンスがそれぞれ保存済みペアリング状態のコピーを持ち、全体を書き戻していたため、一方で行った取り消しや新しいペアリングリンクがもう一方に静かに巻き戻されることがありました。同じプロセス内のすべてのインスタンスは、データディレクトリごとに単一のペアリング状態を共有するようになりました。取り消しとローテーションは即座にすべてに反映され、ファイルへの書き込みはちょうど 1 か所に集約されます。ファイルは本当の再起動をまたぐ正となるデータのままです。

- **失敗したログインの繰り返しは抑制されます。** アクセスパスワードの検証には意図的に計算コストの高い Argon2id を使っており、ポートに到達できる相手なら誰でも試行できます。同じアドレスから 5 回失敗すると、以降の試行はハッシュ計算が始まる前に 1 分間拒否されます。ハッシュ計算自体もサーバーのイベントループの外で実行され、同時に走る検証数には固定の上限があります。誤ったパスワードの洪水でサーバーをメモリハードなハッシュ計算で飽和させたり、接続済みデバイスの応答を遅らせたりすることはもうできません。この抑制はメモリ上にあり、サーバーの再起動でリセットされます。実際の防壁はペアリングトークンとパスワードのままです。この制限は同じデータディレクトリを使うすべてのサーバーインスタンスで共有されるようになり、`--serve` の二重インスタンス構成でも試行回数の予算が倍になることはありません。また、パスワード検証が始まる前に試行が予約されるため、同一アドレスからの並列リクエストが制限をすり抜けることもできません。制限中のブラウザには、パスワードが違うという表示ではなく、ログイン画面に専用のレート制限メッセージが表示されます。また、制限は間違ったパスワードのようには記憶されなくなりました。待ち時間が過ぎれば、ページを再読み込みしなくても次の試行が再び通ります。途中で放棄された試行(パスワードの検証中にタブが閉じられた場合)は、残りの 1 分間そのアドレスに数え続けられるのではなく、予約された枠を即座に解放するようになりました。また、ログインに成功しても解放されるのは自分の予約だけで、そのアドレスの記録全体は消去されません。共有ネットワークアドレスの背後では、誰かが正しくログインしても攻撃者の試行予算はリセットされず、記録された失敗はその 1 分が経過して初めて期限切れになります。

- **ディスク上とログの中の秘密情報を、より慎重に扱うようになりました。** ペアリング状態のファイルとエンドツーエンド暗号化の鍵は、最初の書き込み後に制限するのではなく、作成時点から所有者だけが読めるように作られます。パスワードのハッシュを含むセッションデータベースも所有者のみに制限されます。ヘッドレスの `--serve` は、ペアリングリンクの長命な秘密をログに出力しなくなりました。出力先がターミナルでない場合はリンクを伏せて案内を表示し、`--print-pairing` で明示的に元の動作へ戻せます。デバイスレジストリは名前の長さを制限したうえで 32 件までに制限され、ペアリング済みクライアントが保存ファイルを際限なく肥大させることはできません。取り消しや新しいペアリングリンクの保存に失敗した場合、そのエラーはログの 1 行ではなく呼び出し元に届きます。自動開始は手動で起動済みのサーバーを置き換えなくなり、古い自動開始のエラーはサーバーを自分で停止すると消えます。

### 修正
