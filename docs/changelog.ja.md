## 未リリース

### リモートアクセス

- **共有リンクが使うアドレスを選べるようになり、Tailscale のアドレスも表示されます。** アドレス一覧は従来のプライベート IPv4 範囲しか受け付けなかったため、キャリアグレード NAT 範囲(100.64.0.0/10)のアドレスを割り当てる Tailscale などの VPN メッシュは、サーバーがすでにその経路で到達可能だったにもかかわらず、リモートアクセスパネルとペアリングリンクから黙って除外されていました。これらのアドレスが一覧に表示されるようになり、VPN トンネルは既定にならないよう最後に並びます。パネルに追加された IP セレクター(起動前と実行中の両方で表示)は、各候補をインターフェイス名付きで示し、VPN トンネルに印を付けます。アドレスを選ぶとその URL が先頭に移動し、ペアリングリンクがまさにそのホストで再生成されるため、コピーしたリンクは VPN 経由でしかこのマシンに届かない端末でも、URL を手で編集することなくそのまま使えます。ペアリングリンクの下の QR コードはスマートフォンで直接読み取れます。選択は記憶され、選んだインターフェイスが消えた場合は選択を忘れることなく「自動」に戻ります。サーバー自体は変わらず、引き続きすべてのインターフェイスで待ち受けます。サーバー起動後に現れたアドレス(たとえば後から接続した VPN)を選んだ場合、これまでは次回の再起動までペアリングリンクしか追従しませんでしたが、コピーされる URL と QR コードも即座に更新されるようになりました。VPN トンネルはどのプラットフォームでも LAN アドレスの後ろに並び、サーバー停止中に選んだアドレスは起動後の最初のペアリングリンクに使われ、重なり合ったリンク再生成が新しいリンクを古いリンクで上書きすることもなくなりました。

- **共有が再起動後も維持されるようになりました。** これまでペアリングトークンはサーバーの起動のたびに再生成されていたため、VelaTerm を終了して開き直すと共有済みのリンクはすべて静かに無効になり、どの端末もペアリングをやり直す必要がありました。トークン、ペアリング済み端末、端末のブロックリストは、データディレクトリ内の所有者のみが読めるファイルに保存されるようになりました。ペアリング済みの端末は再起動後も保存された URL でそのまま再接続でき（アクセスパスワードは引き続き必須の第 2 要素です）、ブロックした端末はブロックされたままです。さらに VelaTerm は共有が有効だったことを記憶します。サーバーが動作したままアプリを終了すると、次回の起動時に同じポートで自動的に再開されます — デスクトップアプリでも、`--serve` で動く GUI なしのサーバーでも同様です。自分で停止した場合は、次回何も自動起動しません。ポートが使用中などの理由で自動起動に失敗しても、アプリは通常どおり起動し、リモートアクセスパネルに原因が表示されます。ポート欄は既定値に戻らず、実際に使ったポートを記憶するようになりました。「リンクを再生成」は引き続き明示的な無効化手段です。即座に新しいトークンを発行し、古いリンクをすべて無効にして、保存された状態を上書きします。アクセスパスワード自体がディスクに書き込まれることはなく、保存されるのはメモリハードなハッシュ（Argon2id）のみです。

### セキュリティ

- **ペアリング済みデバイスから共有そのものを管理できなくなりました。** これまで、ペアリング済みのブラウザはデスクトップアプリと同じ管理コマンドを呼び出せました――新しいペアリングリンクの作成(デバイスのブロックリストも消去されます)、他のデバイスの一覧表示や取り消し、サーバーの停止や再設定など。さらに設定ストアは、アクセスパスワードのメモリハードなハッシュや、次回起動時に読み込まれる自動開始の設定を含む設定一式をどのクライアントにも渡していました。管理コマンドは今後デスクトップアプリと Electron シェル専用になり、設定 API はペアリング済みデバイスからの読み取りでリモートアクセス関連のキーと Gitea トークンを除外し、それらへの書き込みを拒否します。ペアリング済みデバイスは本来の役割――ターミナルセッションと完全なシェルアクセス――をそのまま保ちますが、パスワードの検証値を読むことも、他のデバイスを招き入れたり追い出したりすることも、次回起動が使うポートを書き換えることもできなくなりました。保存されたシークレットを読み書き・削除するコマンド — Gitea トークンや記憶されたホストのパスワード — もペアリング済みデバイスからは拒否されるようになり、パスを受け取るコマンド――読み取り、プレビュー、書き込み、作成、名前変更、削除、さらにファイルの git 差分表示やリポジトリのクローン先フォルダーの指定――は、シンボリックリンクを先に解決したうえで、ペアリング状態や鍵が置かれている VelaTerm 自身のデータディレクトリ内のパスを拒否します。それ以外のパスは従来どおり機能するため、リモートでのファイル閲覧・編集はそのまま使えます。パスを受け取るすべてのリモートコマンドをテストが列挙するため、新しいコマンドが気づかれずにこのチェックをすり抜けることはできません。これらの保護がリクエストを拒否した場合、ブラウザには生の英語エラーではなく、きちんと翻訳されたメッセージが表示されます。

- **取り消しやリンクの再生成が、二重インスタンス構成でも失われなくなりました。** 自動開始を有効にしたヘッドレスの `--serve` サーバーでは、2 つのサーバーインスタンスがそれぞれ保存済みペアリング状態のコピーを持ち、全体を書き戻していたため、一方で行った取り消しや新しいペアリングリンクがもう一方に静かに巻き戻されることがありました。同じプロセス内のすべてのインスタンスは、データディレクトリごとに単一のペアリング状態を共有するようになりました。取り消しとローテーションは即座にすべてに反映され、ファイルへの書き込みはちょうど 1 か所に集約されます。ファイルは本当の再起動をまたぐ正となるデータのままです。

- **失敗したログインの繰り返しは抑制されます。** アクセスパスワードの検証には意図的に計算コストの高い Argon2id を使っており、ポートに到達できる相手なら誰でも試行できます。同じアドレスから 5 回失敗すると、以降の試行はハッシュ計算が始まる前に 1 分間拒否されます。ハッシュ計算自体もサーバーのイベントループの外で実行され、同時に走る検証数には固定の上限があります。誤ったパスワードの洪水でサーバーをメモリハードなハッシュ計算で飽和させたり、接続済みデバイスの応答を遅らせたりすることはもうできません。この抑制はメモリ上にあり、サーバーの再起動でリセットされます。実際の防壁はペアリングトークンとパスワードのままです。この制限は同じデータディレクトリを使うすべてのサーバーインスタンスで共有されるようになり、`--serve` の二重インスタンス構成でも試行回数の予算が倍になることはありません。また、パスワード検証が始まる前に試行が予約されるため、同一アドレスからの並列リクエストが制限をすり抜けることもできません。制限中のブラウザには、パスワードが違うという表示ではなく、ログイン画面に専用のレート制限メッセージが表示されます。また、制限は間違ったパスワードのようには記憶されなくなりました。待ち時間が過ぎれば、ページを再読み込みしなくても次の試行が再び通ります。途中で放棄された試行(パスワードの検証中にタブが閉じられた場合)は、残りの 1 分間そのアドレスに数え続けられるのではなく、予約された枠を即座に解放するようになりました。また、ログインに成功しても解放されるのは自分の予約だけで、そのアドレスの記録全体は消去されません。共有ネットワークアドレスの背後では、誰かが正しくログインしても攻撃者の試行予算はリセットされず、記録された失敗はその 1 分が経過して初めて期限切れになります。

- **ディスク上とログの中の秘密情報を、より慎重に扱うようになりました。** ペアリング状態のファイルとエンドツーエンド暗号化の鍵は、最初の書き込み後に制限するのではなく、作成時点から所有者だけが読めるように作られます。パスワードのハッシュを含むセッションデータベースも所有者のみに制限されます。ヘッドレスの `--serve` は、ペアリングリンクの長命な秘密をログに出力しなくなりました。出力先がターミナルでない場合はリンクを伏せて案内を表示し、`--print-pairing` で明示的に元の動作へ戻せます。デバイスレジストリは名前の長さを制限したうえで 32 件までに制限され、ペアリング済みクライアントが保存ファイルを際限なく肥大させることはできません。取り消しや新しいペアリングリンクの保存に失敗した場合、そのエラーはログの 1 行ではなく呼び出し元に届きます。自動開始は手動で起動済みのサーバーを置き換えなくなり、古い自動開始のエラーはサーバーを自分で停止すると消えます。

- **バックグラウンドセッションをより明確に管理。** メニューに各セッションの状態を表示し、上限超過ダイアログでは複数タブをまとめて終了できます。
- **安全な終了と多言語更新ノート。** 実行中セッションを停止する前に終了確認を表示し、Codex lifecycle の正確な ID を優先します。自動更新ノートは全組み込み言語に対応しました。

### 画像とドキュメント

- **macOS で画像パスを確実に貼り付け。** WebKit がコピーされた画像をファイルとして公開しない場合でも、VelaTerm がネイティブクリップボードから画像を読み取り、エージェント固有の画像プレースホルダーへ暗黙にフォールバックせず、ファイルパスとしてアップロードするようになりました。リモートウィンドウでは画像貼り付け設定を常に表示し、ファイルパスモードが必要な理由を説明して、利用できないネイティブオプションを無効にします。
- **ソースドキュメントへ画像を貼り付け。** ソースエディタがクリップボード画像に対応しました。保存済みの Markdown ドキュメントでは、画像をドキュメント横の `assets/` に保存して移植可能な Markdown 画像構文を挿入します。未保存の下書きでは画像データを埋め込み、一時ファイルの削除時にも失われないようにします。

### インターフェース

- **コンテキストメニューを常に表示し、正しい項目を対象に。** 右端付近で開くメニューの寸法と位置が正しく調整されるようになりました。ツリーノードを右クリックしても既存の選択は変えず、メニュー対象だけを強調表示します。グループメニューには、そのグループを対象とするターミナルも追加されました。
- **編集表示とステータスラベルを整理。** ソーステキストでは HTML コメントなどの文字列に矢印状のフォント合字を表示しなくなりました。使用率には「使用済み」であることを明記し、ホスト WebView の無関係なネイティブコンテキストメニューが VelaTerm のメニュー背後に表示される問題も解消しました。

### 修正

- **Codex が通常のターミナル履歴に留まるように。** VelaTerm から起動した Codex セッションはインラインターミナルモードを使用するようになりました。Esc で中断または戻ったときに画面バッファが切り替わり、スクロールバック表示が先頭へ飛ぶことはありません。ユーザー自身の Codex 設定は変更されません。
