# Zcode 对话体验补齐

本轮固定点为 `4c85c5fc6d7cf82aa25f889e551da0bb8000dadc`，交付仍采用独立 Windows EXE，PR 使用官方 0.2.10 基线。保留既有账户、会话身份、权限及扩展接入。

## 状态与验收边界

CLI 拥有用户输入、执行中引导、子智能体生命周期及用量事实；VelaTerm 负责原生协议适配与界面投影。测试沿用聊天 IPC、原生 CLI 协议和成品内嵌界面三个已有公共边界。每项先观察失败，再补实现；最终以同一 EXE 的完整回归验收。

### 图片附件

粘贴或上传的图片必须经原生附件协议进入模型请求，保留 MIME 与实际字节；只发送缩略图或占位文字不算成功。图片随原生历史保存，停止并恢复同一会话后仍可显示与读取附件；排队路径不能静默丢图。原生 CLI 的 guide 不支持附件，本轮会在发送前明确拒绝带图追加，保留草稿供普通发送或排队使用，不将原生降级排队冒充即时追加。供应商拒绝图片时显示原生错误，不声称模型已读图。

### 执行中即时追加指令

用户明确选择 steer 时，将输入交给 CLI 的当前执行引导入口，保留原始执行，不伪装成中断后新开一轮或普通排队。相同已提交输入不能重复执行；迟到事件不得结束新的回合。原生拒绝或执行已结束时要明确反馈；权限等待与恢复仍沿用原有规则。普通 queue 和 interrupt 的行为保持有效。

### 内部 subagent 可视化

原生 Agent 工具启动的子智能体须在对应工具卡片展示运行或结束状态、名称或描述、模型及可获得的过程与统计；原生存在的子工具、回复须能展开查看。先到子事件、晚到父卡片、并发子智能体以及停止后恢复都不能错绑、串话或复制卡片。原生子会话保持只读；本轮不额外承诺把内部子任务变成可独立输入的左侧 VelaTerm 会话。

### 用量面板

显示 CLI 实际报告的 token 输入、输出、缓存、上下文已用量与容量；会话总量和本轮数据必须区分，恢复后不重复累计。容量或费用未知时保留未知，不写固定容量或虚构价格。Start Plan 权益余额与模型 token 统计是不同事实。复用现有侧栏、用量控件和统计组件，支持较小窗口与键盘操作。

## 事件顺序

```text
附件/引导输入 → 原生 CLI 准入 → 当前执行/后续执行 → 有序事件 → 对应会话投影
原生 Agent → 子会话身份与归属 → 子事件/只读快照 → 对应父工具卡片
原生用量 → 当前执行及会话累计 → 上下文/统计面板（未知字段保持未知）
```

交付前覆盖实际模型请求载荷、引导后的实际响应、真实原生 Agent 执行、恢复及统计，并完成完整 CLI/隔离供应商/浏览器回归。既有全仓库基线失败单独报告，不能用聚焦测试冒充全仓通过。

## 已确认的协议口径

- 图片使用原生 `session/send` 附件；恢复读取原生历史内联图片，附件详情仍经 VelaTerm 现有接口返回。
- 纯文字 steer 使用原生 V4 `sendText` / `guide`；附图 steer 在写入原生协议前拒绝，避免原生回退排队后的重复发送。权限确认未处理时先要求处理确认。
- 引导准入先显示等待状态；原生 `turn.steerDrained` 明确采用 guide 后才报告追加成功。原生因中断或无法安全内联而改投 queue 时，读取有序 V4 队列事实提示后续排队，不重发输入。纯文本模型步骤完成也可以是原生的内联边界，并非一定要调用工具。准入期间原回合结束时单独提示已接收、等待实际回复。
- 原生子任务通过有归属证明的 V4 conversation topic 投影到 Agent 卡片，内部子任务保持只读。初次过程使用原生最近历史窗口，深层嵌套最多显示八级。
- 上下文容量以 V4 投影为准。原生 V4 冷恢复的累计字段可能为零，任务 usage 查询又采用增量输入口径，因此会话原始累计来自原生持久化 assistant token 记录；每次查询整体替换，不叠加旧值。当前回合使用原生完成事件中的 usage，恢复时不猜测缺失的回合统计。
