### AI 에이전트

- **하위 작업 카드가 이제 각 에이전트의 실제 모델과, 그 에이전트가 알아듣는 강도 플래그를 보여 줍니다.** 카드는 어떤 에이전트든 `--model`과 `--effort`로 실행 인자를 만들었지만, 추론 강도를 그렇게 부르는 것은 Claude와 Kiro, Antigravity뿐입니다 — Grok과 Zoo는 `--reasoning-effort`, Cline은 `--thinking`이라고 합니다. 그래서 나머지 에이전트에서 강도를 고르면 CLI가 한 번도 들어 본 적 없는 플래그가 전달되었고, 세션은 시작되지 못했습니다. 이제 플래그 이름도 값도 각 에이전트가 직접 내놓습니다. 모델 선택란은 각 CLI가 알려 줄 수 있는 만큼을 따릅니다. 목록을 뽑아 줄 수 있는 쪽(OpenCode, Grok, Crush, Antigravity, Cursor, pi, Kiro)에는 물어봐서 실제 목록을 보여 주고, 정해진 집합이 있는 쪽(Claude, Codex, Kimi Code)은 그 집합을 보여 주며, 나머지는 어떤 형태를 기대하는지 예시를 곁들인 입력란으로 대신합니다. 설치되지 않았거나 로그인하지 않은 에이전트는 끝없이 돌아가는 대신 그 사실을 알려 줍니다. "기본값"을 고르면 예전 값이 남아 있는 대신 물려받은 설정이 해제되고, 강도를 골라도 부모 세션에서 물려받은 모델이 더 이상 빠지지 않습니다.

### 작업 공간

- **그룹을 만든 뒤에도 worktree로 옮길 수 있습니다.** worktree는 그룹을 만들 때 고르고 나면 그대로 고정이라, 생각이 바뀌면 그룹을 지우고 다시 만드는 수밖에 없었습니다. 이제 그룹을 오른쪽 클릭하고 "Move to Worktree…"를 고르면 새 worktree를 만들거나, 이미 있는 것을 연결하거나, 이미 연결된 그룹의 대상을 바꿀 수 있습니다. 바뀌는 것은 그룹 자체뿐입니다. 안에 이미 있는 세션은 만들어질 때의 디렉터리를 그대로 쓰고 — 실행 중인 세션을 그 아래의 다른 디렉터리로 옮길 수는 없습니다 — 그 뒤에 만드는 세션이 worktree에서 시작합니다.

- **미러 모드가 사이드바 트리 전체를 다룹니다.** 지금까지 공유된 것은 선택 상태와 접어 둔 패널뿐이었고, 검색창과 상태·마커 필터는 각자 로컬에 남았습니다. 그것까지 동기화하면 뭔가를 찾아보는 사람을 방해한다고 봤기 때문입니다. 이 판단은 거꾸로였습니다. 미러란 두 창이 같은 상태를 갖는다는 뜻이지, 한쪽이 다른 쪽의 키 입력을 따라 친다는 뜻이 아닙니다 — 여기서 켜진 필터는 저기서도 켜져 있습니다. 정작 사람을 방해하는 것은 양쪽이 서로 다른 트리를 보여 주는 쪽입니다. 이제 사이드바의 모든 표시가 그대로 전달됩니다. 분할 레이아웃, 각 표시의 이름, 검색어, 상태와 마커 필터, 그리고 저마다의 접힘 상태까지입니다. 스냅샷 형식은 버전 2로 올라갔고, 이전 버전을 쓰는 클라이언트는 한 프레임의 절반만 적용하는 대신 미러링을 멈춥니다. 업그레이드하는 동안 열어 둔 창이 있다면 새로 고쳐 주세요.

## v0.1.102 — 2026-08-23

### AI 에이전트

- **에이전트 프리셋 — 호환되는 CLI를 여러 개 나란히 쓸 수 있습니다.** 지금까지 에이전트 종류는 실행 파일 하나에 고정되어 있어서, 포크 버전이나 나이틀리 빌드, 같은 프로토콜을 쓰는 다른 CLI를 들여올 방법이 없었습니다. 기존 종류의 실행 인자를 고쳐 쓰는 수밖에 없었고, 그러면 원래 설정은 사라졌습니다. 이제 프리셋은 자기 실행 파일과 아이콘, 실행 인자를 직접 갖고, 새 세션 메뉴에서 기본 제공 종류와 나란히 표시됩니다. 세션은 어떤 프리셋으로 만들어졌는지 기록하므로 포크해도 같은 실행 파일을 그대로 씁니다. 데스크톱에서 만든 프리셋은 페어링된 브라우저와 원격 클라이언트에도 아이콘까지 그대로 나타납니다. 아이콘이 한 컴퓨터의 경로가 아니라 데이터로 전달되기 때문입니다. 기존 세션은 전혀 건드리지 않으므로, 이전 버전에서 쓰던 데이터베이스도 예전과 똑같이 시작됩니다.

- **하위 작업 확인 카드에서 모델과 추론 강도를 고르고, 한 번 답하면 모든 곳에 반영됩니다.** 에이전트가 하위 작업 실행을 요청하면 이제 확인 카드에 모델 선택과 — 에이전트가 지원하는 경우 — 추론 강도 선택이 함께 표시됩니다. 둘 다 부모 세션의 실행 인자에서 미리 채워지므로 보통은 클릭 한 번이면 끝납니다. 카드에서 다른 에이전트로 바꾸면 둘 다 다시 계산되기 때문에, 한 CLI의 모델 이름이 다른 CLI의 명령줄에 섞여 들어갈 일이 없어졌습니다. 카드는 연결된 모든 클라이언트에 표시되며, 어느 한 곳에서 답하면 나머지에서는 사라집니다. 첫 응답이 서버에서 해당 작업을 선점하므로, 휴대폰과 데스크톱에서 같은 1초 안에 확인하더라도 worktree와 하위 세션은 두 개가 아니라 하나만 만들어집니다.

### 인터페이스

- **⌘Q도 창을 닫을 때와 같은 질문을 합니다.** 애플리케이션 메뉴의 종료 항목은 시스템이 제공하는 것이라 프로세스를 곧바로 끝냈습니다. 그래서 ⌘Q를 누르면 닫기 버튼에서는 나오는 "작업 공간 저장" 확인이 건너뛰어졌고, 같은 의도의 동작이 어떻게 실행하느냐에 따라 다르게 작동했습니다. 이제 두 경로 모두 하나의 확인을 거칩니다. 확인을 띄우는 창이 그사이에 새로 고쳐졌거나 멈춰 버렸다면, ⌘Q를 다시 누를 때 확인을 다시 요청하고 그래도 안 되면 네이티브 대화 상자로 대체합니다. 앱을 종료할 수 없는 상태로 남겨 두지 않습니다.

- **단축키 안내가 실제로 동작하는 키를 보여 줍니다.** 기본 단축키는 플랫폼마다 다르고, 브라우저는 ⌘/Ctrl과 문자 조합을 자기 몫으로 예약해 둡니다 — ⌘D는 북마크, ⌘T는 새 탭. 그래서 macOS에서는 VelaTerm을 URL로 열었을 때 앱 자체의 ⌘ 단축키가 페이지까지 도달하지 못했습니다. 이제 일반 브라우저 탭에서는 어떤 운영체제든 Ctrl+Alt 조합을 쓰고, 데스크톱 앱과 원격 접속 창은 ⌘를 그대로 유지합니다. 툴팁과 빈 탭 안내는 하드코딩된 ⌘ 조합 대신 실제로 적용 중인 조합을 — 직접 바꾼 것까지 포함해 — 그대로 표시합니다. 그리고 터미널은 앱이 실제로 차지한 조합만 가로채므로, 어떤 동작의 단축키를 바꾸면 그 키의 처리도 함께 옮겨 갑니다.

- **글꼴 프리셋에 Nerd Font와 CJK가 들어왔고, 설치되지 않은 글꼴을 직접 입력하면 그렇다고 알려 줍니다.** 프리셋 목록에 널리 쓰이는 Nerd Font와 CJK 글꼴 계열이 추가되었습니다. 손으로 입력한 글꼴 이름은 그대로 다시 보여 주면서 확인까지 하므로, 시스템에 없는 글꼴이면 요청한 것과 전혀 다른 기본 글꼴로 조용히 되돌아가는 대신 설정 페이지에 그 사실을 표시합니다.

- **macOS의 텍스트 입력란이 입력한 내용을 마음대로 대문자로 바꾸거나 고치지 않습니다.** 시스템의 자동 대문자 변환, 자동 수정, 맞춤법 검사가 앱의 모든 입력란에 적용되어 세션 이름이나 명령 입력란에서도 "npm"이 "Npm"이 되곤 했습니다. 이제 모든 곳에서 꺼져 있습니다.

### Windows

- **중국어·일본어·한국어를 입력할 때 조합 중인 글자와 후보 창이 다시 보입니다.** 둘 다 보이지 않아서, 화면을 보지 못한 채 입력하고 Enter를 눌러야 결과를 확인할 수 있었습니다. 원인은 우리 쪽 CSS 규칙 두 군데였습니다. 조합 중인 글자를 얹는 오버레이의 컨테이너가 너비 0으로 접혔고, 그 안에서 오버레이의 `right` 값이 아무 위치도 가리키지 못했습니다. 운영체제가 오버레이의 사각형을 기준으로 후보 창의 위치를 잡기 때문에 후보 창도 함께 사라졌습니다. 이제 오버레이는 다시 그려지고 앱의 색을 따릅니다. 오버레이가 놓이는 보이지 않는 입력 요소도 조합이 끝나면 영역을 내놓으므로, 그 자리를 클릭하거나 드래그하면 예전처럼 빈 요소에 가로막히지 않고 터미널까지 전달됩니다.

- **네이티브 제목 표시줄이 라이트/다크 설정을 따릅니다.** 이 앱은 시스템 제목 표시줄을 그대로 쓰는데, Windows는 따로 알려 주기 전까지 제목 표시줄을 밝게 그리기 때문에 어두운 화면 위에 흰 띠가 얹혀 있었습니다. 이제 제목 표시줄이 앱과 같은 모습이 되며, SSH나 원격 접속 창처럼 나중에 열리는 창에도 적용됩니다. "시스템 설정 따르기"를 고르면 값을 고정하지 않고 운영체제에 제어를 돌려줍니다.

- **시작할 때 잠깐 나타나던 작은 사각형이 사라졌습니다.** 중복 실행을 막는 플러그인이 숨겨진 메시지 창을 만드는데, 그 창의 스타일이 약속한 투명도를 실제로는 적용해 주지 않았습니다. 그래서 Windows가 크기 0인 창을 최소 크기까지 키워 시작 중에 작은 사각형을 그리는 일이 가끔 있었습니다. 이제 제대로 투명하게 처리했으며, 중복 실행 방지 동작 자체는 그대로입니다.

### 성능

- **원격 접속이 첫 화면을 띄우기까지 받는 양이 훨씬 줄었습니다.** 이제 정적 자산은 요청 시점에 압축해서 캐시 검증 정보와 함께 전달하므로, 두 번째 방문부터는 다시 내려받는 대신 검증만 합니다. 언어 팩과 터미널의 선택적 렌더러도 첫 전송에 포함하지 않고 필요할 때만 불러옵니다. 그 결과 최초 전송량이 예전의 5분의 1 정도로 줄었습니다.

### 수정

- **실행된 하위 세션이 요청한 세션과 같은 조건으로 시작됩니다.** 하위 세션은 부모의 권한 모드도, 실행 인자도 물려받지 않았습니다. 그래서 확인을 건너뛰도록 설정된 세션의 하위 세션이 확인을 요구했고, 부모에 지정해 둔 모델도 빠졌습니다. 이제 둘 다 물려받으며, 없으면 해당 에이전트 종류의 전역 기본값 — "새 에이전트 세션" 메뉴가 적용하는 것과 같은 값 — 으로 되돌아갑니다.

- **원격 창을 다시 연결할 때 "인증 실패"라고 잘못 알리지 않습니다.** 창이 다시 연결할 때 새 WebSocket과 그것이 대체하는 기존 WebSocket이 서로 경쟁했고, 진 쪽의 정리 과정이 인증 실패로 보고되었습니다. 그 결과 아무 문제 없는 페어링이 거부된 것처럼 배너가 표시되었습니다.

- **그룹을 자기 하위 트리 안으로 끌어다 놓을 수 없습니다.** 그룹을 자기 자손 위에 놓으면 그 가지 전체가 트리에서 떨어져 나가, 안에 있던 세션들이 사이드바에서 사라진 뒤 데이터베이스를 손으로 고치기 전까지 돌아오지 않았습니다. 이제 이런 이동은 거부됩니다.

- **다른 도구에서 VelaTerm을 실행해도 에이전트 출력의 색이 유지됩니다.** 터미널은 자기를 실행한 쪽의 환경을 물려받으므로, `NO_COLOR`나 `CI`, `FORCE_COLOR=0`을 내보내는 IDE나 에이전트 실행 환경에서 시작하면 터미널이 풀컬러를 지원한다고 알리는데도 VelaTerm 안의 에이전트 TUI가 모두 흑백으로 그려졌습니다. 이제 세션이 시작될 때 이렇게 물려받은 값들을 제거합니다. 사용자의 셸 프로필에서 내보낸 같은 변수는 그대로 적용됩니다. 그 프로필은 세션 안에서 실행되기 때문입니다.

## v0.1.101 — 2026-08-15

### 원격 액세스

- **공유가 재시작 후에도 유지됩니다.** 지금까지는 서버가 시작될 때마다 페어링 토큰이 새로 생성되어, VelaTerm을 종료했다가 다시 열면 공유한 링크가 모두 조용히 무효화되고 모든 기기를 다시 페어링해야 했습니다. 이제 토큰, 페어링된 기기, 기기 차단 목록이 데이터 디렉터리의 소유자 전용 파일에 저장됩니다. 이미 페어링된 기기는 재시작 후에도 저장된 URL로 다시 연결되며(액세스 비밀번호는 여전히 필수 2차 인증 요소입니다), 차단된 기기는 계속 차단된 상태로 남습니다. 또한 VelaTerm은 공유가 켜져 있었다는 사실을 기억합니다. 서버가 실행 중인 상태로 앱을 종료하면 다음 실행 시 같은 포트에서 자동으로 다시 시작됩니다 — 데스크톱 앱에서든 `--serve`로 동작하는 GUI 없는 서버에서든 동일합니다. 직접 중지한 경우에는 아무것도 자동으로 시작되지 않습니다. 포트가 사용 중인 경우처럼 자동 시작이 실패해도 앱은 정상적으로 실행되며 원격 액세스 패널에 원인이 표시됩니다. 포트 입력란은 기본값으로 되돌아가지 않고 실제로 사용한 포트를 기억합니다. "링크 재생성"은 여전히 명시적인 무효화 수단입니다. 즉시 새 토큰을 발급하고 기존 링크를 모두 무효화하며 저장된 상태를 덮어씁니다. 액세스 비밀번호 자체는 절대 디스크에 기록되지 않으며, 저장되는 것은 메모리 하드 해시(Argon2id)뿐입니다.

### 원격 접속

- **공유 링크가 사용할 주소를 선택할 수 있고, Tailscale 주소도 이제 표시됩니다.** 주소 목록이 기존의 사설 IPv4 대역만 허용했기 때문에, 캐리어급 NAT 대역(100.64.0.0/10)의 주소를 할당하는 Tailscale 같은 VPN 메시는 서버가 이미 그 경로로 접근 가능했음에도 원격 접속 패널과 페어링 링크에서 조용히 제외되었습니다. 이제 이 주소들이 목록에 표시되며, VPN 터널은 기본값이 되지 않도록 맨 뒤에 배치됩니다. 패널에 추가된 IP 선택기(시작 전과 실행 중 모두 표시)는 각 후보를 인터페이스 이름과 함께 보여 주고 VPN 터널을 표시합니다. 주소를 선택하면 해당 URL이 맨 앞으로 이동하고 페어링 링크가 정확히 그 호스트로 다시 생성되므로, 복사한 링크는 VPN을 통해서만 이 컴퓨터에 도달할 수 있는 기기에서도 URL을 손으로 수정하지 않고 그대로 동작합니다. 페어링 링크 아래의 QR 코드는 휴대폰으로 바로 스캔할 수 있습니다. 선택은 기억되며, 선택한 인터페이스가 사라지면 선택을 잊지 않은 채 ‘자동’으로 되돌아갑니다. 서버 자체는 변경되지 않았고 계속 모든 인터페이스에서 수신 대기합니다. 서버 시작 후에야 나타난 주소(예: 나중에 연결된 VPN)를 선택하면 이제 페어링 링크뿐 아니라 복사되는 URL과 QR 코드도 즉시 갱신됩니다(예전에는 다음 재시작까지 페어링 링크만 따라갔습니다). VPN 터널은 모든 플랫폼에서 LAN 주소 뒤에 정렬되고, 서버가 중지된 상태에서 고른 주소는 시작 후 첫 페어링 링크에 사용되며, 겹치는 링크 재생성이 더 새로운 링크를 더 오래된 링크로 덮어쓰는 일도 없어졌습니다.

### 보안

- **페어링된 기기가 더 이상 공유 자체를 관리할 수 없습니다.** 지금까지는 페어링된 브라우저가 데스크톱 앱과 동일한 관리 명령을 호출할 수 있었습니다 — 새 페어링 링크 생성(기기 차단 목록도 함께 비워집니다), 다른 기기 목록 조회와 해지, 서버 중지와 재구성까지. 또한 설정 저장소는 접근 비밀번호의 메모리 하드 해시와 다음 실행이 읽는 자동 시작 설정을 포함한 전체 설정을 모든 클라이언트에 넘겨주었습니다. 이제 관리 명령은 데스크톱 앱과 Electron 셸 전용이며, 설정 API는 페어링된 기기의 읽기에서 원격 접속 키와 Gitea 토큰을 걸러내고 해당 키에 대한 쓰기를 거부합니다. 페어링된 기기는 페어링의 본래 목적 — 터미널 세션과 완전한 셸 접근 — 은 그대로 유지하지만, 비밀번호 검증값을 읽거나 다른 기기를 초대·추방하거나 다음 시작이 사용할 포트를 바꿀 수는 없습니다. 저장된 비밀 정보를 읽거나 쓰거나 삭제하는 명령 — Gitea 토큰과 기억된 호스트 비밀번호 — 도 이제 페어링된 기기에서는 거부되며, 경로를 받는 명령 — 읽기, 미리보기, 쓰기, 생성, 이름 바꾸기, 삭제는 물론 파일의 git diff 표시와 저장소를 복제할 폴더 선택까지 — 은 심볼릭 링크를 먼저 해석한 뒤 페어링 상태와 키가 보관된 VelaTerm 자체 데이터 디렉터리 내부 경로를 거부합니다. 그 외의 모든 경로는 그대로 동작하므로 원격 파일 탐색과 편집은 계속 사용할 수 있습니다. 경로를 받는 모든 원격 명령을 테스트가 열거하므로, 새 명령이 이 검사를 몰래 지나칠 수 없습니다. 이러한 보호 장치가 요청을 거부하면 브라우저에는 이제 영어 원문 오류 대신 제대로 번역된 메시지가 표시됩니다.

- **해지나 링크 재생성이 이중 인스턴스 구성에서도 유지됩니다.** 자동 시작을 켠 헤드리스 `--serve` 서버에서는 두 서버 인스턴스가 각자 저장된 페어링 상태 사본을 들고 전체를 다시 써서, 한쪽에서 수행한 해지나 새 페어링 링크가 다른 쪽에 의해 조용히 되돌려질 수 있었습니다. 이제 한 프로세스의 모든 인스턴스는 데이터 디렉터리별로 단일 페어링 상태를 공유합니다. 해지와 회전은 즉시 모든 곳에 적용되고, 파일 기록은 정확히 한 곳으로 모입니다. 파일은 실제 재시작을 넘어 유효한 원본으로 남습니다.

- **반복된 로그인 실패는 제한됩니다.** 접근 비밀번호 검증은 의도적으로 비용이 큰 Argon2id를 사용하며, 포트에 도달할 수 있는 누구나 시도할 수 있습니다. 같은 주소에서 다섯 번 실패하면 이후 시도는 해시 작업이 시작되기 전에 1분 동안 거부됩니다. 해시 계산 자체도 이제 서버의 이벤트 루프 밖에서 실행되며 동시 검증 수에 엄격한 상한이 있습니다. 잘못된 비밀번호를 쏟아부어도 서버를 메모리 하드 해시로 포화시키거나 이미 연결된 기기의 응답을 늦출 수 없습니다. 이 제한은 메모리에만 존재하며 서버 재시작으로 초기화됩니다. 실제 방벽은 여전히 페어링 토큰과 비밀번호입니다. 이 제한은 이제 같은 데이터 디렉터리를 사용하는 모든 서버 인스턴스가 공유하므로 `--serve` 이중 인스턴스 구성에서도 시도 예산이 두 배가 되지 않으며, 비밀번호 검증이 시작되기 전에 시도가 예약되므로 한 주소에서 오는 병렬 요청이 제한을 빠져나갈 수 없습니다. 제한된 브라우저에는 이제 비밀번호가 틀렸다는 안내 대신 로그인 화면에 전용 속도 제한 메시지가 표시됩니다. 또한 속도 제한은 더 이상 틀린 비밀번호처럼 기억되지 않습니다. 대기 시간이 지나면 페이지를 새로 고치지 않아도 다음 시도가 다시 처리됩니다. 중간에 중단된 시도(비밀번호 검증 중에 탭이 닫힌 경우)는 이제 남은 1분 동안 해당 주소에 계속 집계되는 대신 예약된 자리를 즉시 해제합니다. 또한 로그인에 성공해도 자신의 예약만 해제될 뿐 해당 주소의 기록 전체가 지워지지는 않습니다. 공유 네트워크 주소 뒤에서는 누군가 올바르게 로그인해도 공격자의 시도 예산이 초기화되지 않으며, 기록된 실패는 해당 1분이 지나야만 만료됩니다.

- **디스크와 로그의 비밀 정보를 더 신중하게 다룹니다.** 페어링 상태 파일과 종단 간 암호화 키는 첫 기록 후에 제한하는 대신 생성 시점부터 소유자만 읽을 수 있게 만들어지고, 비밀번호 해시가 담긴 세션 데이터베이스도 소유자로 제한됩니다. 헤드리스 `--serve`는 페어링 링크의 수명이 긴 비밀을 더 이상 로그에 출력하지 않습니다. 출력이 터미널이 아니면 링크를 감추고 안내만 표시하며, `--print-pairing`으로 명시적으로 되돌릴 수 있습니다. 기기 레지스트리는 이름 길이를 제한한 32개 항목으로 상한이 정해져 페어링된 클라이언트가 저장 파일을 무한정 키울 수 없고, 해지나 새 페어링 링크 저장이 실패하면 그 오류가 로그 한 줄이 아니라 호출자에게 전달됩니다. 자동 시작은 이미 수동으로 시작된 서버를 더 이상 대체하지 않으며, 오래된 자동 시작 오류는 서버를 직접 중지하면 사라집니다.

## v0.1.97 — 2026-07-25

### AI 에이전트

- **세션이 더 이상 “작업 중” 상태로 멈추지 않습니다.** Codex는 도구 활동과 턴 종료를 각각 별도의 짧은 프로세스로 전달하기 때문에 콜백 도착 순서가 뒤바뀌어 이미 끝난 턴이 계속 작업 중으로 표시될 수 있었습니다. 이제 자신의 턴이 끝난 뒤 도착한 중간 보고는 폐기하며, 완료 이벤트 없이 종료되는 세션을 위해 세션 종료 hook을 추가했습니다.
- **중단된 턴이 몇 초 만에 정리됩니다.** Esc를 누르거나 스트림 오류가 발생하면 Claude와 Codex의 턴은 완료 콜백을 전혀 보내지 않습니다. 이제 터미널이 6초 동안 아무것도 출력하지 않으면 해당 세션을 조용히 대기 중으로 교정하며 “응답함” 알림은 띄우지 않습니다.

### 인터페이스

- **macOS에서 분할 단축키가 안정적으로 동작합니다.** 오른쪽 분할(Cmd+D)과 아래쪽 분할(Cmd+Shift+D)을 네이티브 Terminal 메뉴 명령으로도 등록해, macOS가 VelaTerm보다 먼저 키 입력을 가로채지 않습니다.
- **한 번의 키 입력에 한 번만 저장합니다.** Cmd+S가 전역 단축키와 포커스된 편집기 양쪽에서 처리되어 한 번의 입력으로 같은 파일을 두 번 기록할 수 있었습니다.

## v0.1.96 — 2026-07-23

### AI 에이전트

- **Codex 상태는 터미널 추측이 아닌 lifecycle hooks를 신뢰합니다.** 최신 Codex 세션은 공식 lifecycle hooks만 활동 상태의 기준으로 사용합니다. `SessionStart` 핸드셰이크로 연결을 확인하고, 콜백이 없으면 “상태 확인 불가”로 표시합니다. 터미널 텍스트나 출력 활동이 작업 중, 확인 필요 또는 완료 상태를 덮어쓰는 일도 없습니다.
- **각 턴이 끝난 뒤 Codex 사용량을 더 빠르게 갱신합니다.** Info 패널은 로컬 rollout 스냅샷을 즉시 표시한 다음 실시간 사용 한도와 대조합니다. Codex가 최종 token 스냅샷을 기록한 뒤 한 번 더 갱신하며, 이전 세션에서 늦게 도착한 응답은 무시합니다.

### 인터페이스

- **macOS에서 프로젝트 트리를 정확하게 조작합니다.** 가상 행이 더 이상 컴포지터 transform에 의존하지 않아, 스크롤이나 트리 갱신 후 WKWebView의 오래된 히트 테스트 좌표 때문에 호버, 클릭 또는 드래그가 다른 행으로 전달되는 문제를 방지합니다.

## v0.1.95 — 2026-07-21

### AI 에이전트

- **Kimi Code와 Zoo Code가 세션 트리에 추가되었습니다.** 두 에이전트를 시작, 재개, 설치 및 구성할 수 있습니다. Kimi는 공식 lifecycle hooks로 작업·권한·대기 상태를 정확히 보고하며, Zoo Code는 안정적인 작업 ID와 터미널 감지를 사용합니다.
- **Codex 사용량 실시간 새로 고침.** Info 패널이 Codex app server에서 현재 사용 한도를 조회하며, 실패하면 로컬 rollout 스냅샷으로 호환성 있게 돌아갑니다.

### 프로젝트와 터미널

- **`vela <path>`로 프로젝트 열기.** 패키지 빌드에서 VS Code 스타일 shell 명령을 설치할 수 있습니다. 두 번째 호출은 중복 창을 만들지 않고 기존 VelaTerm 창으로 프로젝트를 전달합니다.
- **진행 상황을 표시하고 취소할 수 있는 Git 복제.** Git 단계, 백분율, 경과 시간을 표시하고 정체 시 경고합니다. 취소하면 Git 프로세스 트리와 미완성 디렉터리를 정리하며 오류 및 감사 로그에서 자격 증명과 query token을 숨깁니다.
- **Windows의 WSL 터미널.** 설치된 모든 WSL 배포판을 감지하여 일반 터미널에서 PowerShell, cmd, Git Bash와 함께 선택할 수 있습니다. 에이전트 세션은 hooks와 실행 경로의 안정성을 위해 Windows 호스트 shell을 계속 사용합니다.

### 인터페이스와 안정성

- **더 명확한 백그라운드 세션 제어.** 메뉴에 각 세션의 실시간 상태가 표시되고, 제한 초과 대화상자에서 여러 탭을 한 번에 종료할 수 있습니다.
- **더 안전한 종료와 다국어 업데이트 노트.** 실행 중인 세션을 중지하기 전에 종료를 확인하고 Codex lifecycle의 정확한 ID를 우선합니다. 자동 업데이트 노트는 모든 내장 언어를 지원합니다.

## v0.1.94 — 2026-07-12

### 현지화

- **베트남어 인터페이스.** 이제 언어 선택기에서 Tiếng Việt를 사용할 수 있으며, 베트남어 시스템 로캘에서는 자동으로 선택됩니다.

### 브라우저

- **내장 브라우저의 더 빠른 시작.** 이제 모든 브라우저 탭에 ChatGPT, Claude, Gemini 및 Google을 한 번의 클릭으로 여는 바로 가기가 있습니다. 프로젝트와 그룹의 컨텍스트 메뉴에서도 세션 트리의 해당 위치에 고정 브라우저 페이지를 바로 만들 수 있습니다.

### 이미지 및 문서

- **macOS에서 안정적인 이미지 경로 붙여넣기.** WebKit이 복사된 이미지를 파일로 노출하지 않는 경우에도 VelaTerm이 네이티브 클립보드에서 이미지를 읽어 파일 경로로 업로드합니다. 에이전트 고유의 이미지 자리 표시자로 조용히 대체되지 않습니다. 원격 창에는 이미지 붙여넣기 설정이 항상 표시되며, 파일 경로 모드가 필요한 이유를 설명하고 사용할 수 없는 네이티브 옵션을 비활성화합니다.
- **소스 문서에 이미지 붙여넣기.** 이제 소스 편집기에서 클립보드 이미지를 붙여넣을 수 있습니다. 저장된 Markdown 문서는 문서 옆의 `assets/`에 이미지를 저장하고 이식 가능한 Markdown 이미지 구문을 삽입합니다. 저장하지 않은 초안은 이미지 데이터를 포함하므로 임시 파일이 정리될 때도 이미지가 사라지지 않습니다.

### 인터페이스

- **컨텍스트 메뉴를 계속 표시하고 올바른 항목을 대상으로 지정.** 오른쪽 가장자리 근처에서 열린 메뉴의 크기와 위치가 올바르게 조정됩니다. 트리 노드를 마우스 오른쪽 버튼으로 클릭하면 기존 선택은 바뀌지 않고 메뉴 대상만 강조됩니다. 그룹 메뉴에는 해당 그룹 범위의 터미널도 포함됩니다.
- **더 깔끔한 편집 표시와 상태 레이블.** 소스 텍스트가 HTML 주석 같은 문자열에 화살표 모양의 글꼴 합자를 더 이상 표시하지 않습니다. 사용량 백분율에는 사용된 값임을 명시하며, 호스트 WebView의 관련 없는 네이티브 컨텍스트 메뉴가 VelaTerm 메뉴 뒤에 나타나지 않습니다.

### 수정

- **Codex가 일반 터미널 기록에 유지됩니다.** VelaTerm에서 시작한 Codex 세션은 이제 인라인 터미널 모드를 사용합니다. 따라서 Esc를 눌러 중단하거나 뒤로 이동해도 터미널 화면 버퍼가 전환되거나 스크롤백 뷰포트가 맨 위로 이동하지 않습니다. 사용자의 Codex 설정은 변경되지 않습니다.
